## Java String 비교

```java
String a = "java";
String b = new String("java");

System.out.println((a == b) + " " + a.equals(b));
```

처음에는 문제 자체를 어떻게 읽어야 하는지 헷갈렸다.

특히:

```java
a == b
```

와

```java
a.equals(b)
```

의 차이,

그리고

```java
(a == b) + " " + a.equals(b)
```

에서 `+`가 왜 나오는지도 다시 확인했다.

### 다시 이해한 내용

```text
==
→ 두 변수가 같은 객체를 가리키는지 비교

.equals()
→ String의 문자열 내용이 같은지 비교
```

쉽게 생각하면:

```text
a → ["java"] 객체 1
b → ["java"] 객체 2
```

내용은 둘 다 `"java"`지만  
서로 다른 객체를 가리킬 수 있다.

따라서:

```text
a == b
→ false

a.equals(b)
→ true
```

그리고:

```java
false + " " + true
```

처럼 문자열 `" "`가 중간에 들어가면  
여기서 `+`는 숫자 덧셈이 아니라 **문자열 이어붙이기**가 된다.

결과:

```text
false true
```

설명을 다시 본 뒤에는 이 문제를 `③ false true`로 풀 수 있었다.

## Python List Slicing

```python
a = [1, 2, 3, 4, 5]

print(a[1:4], a[-1])
```

정답은 맞혔지만

```python
a[1:4]
```

가 정확히 어떤 위치를 꺼내는지 다시 확인했다.

인덱스:

```text
값      1  2  3  4  5
인덱스  0  1  2  3  4
```

따라서:

```python
a[1:4]
```

는

```text
인덱스 1
인덱스 2
인덱스 3
```

을 가져온다.

결과:

```text
[2, 3, 4]
```

핵심:

```text
[시작:끝]

시작 → 포함
끝   → 포함하지 않음
```

그리고:

```python
a[-1]
```

은 마지막 값을 의미한다.

## Python Dictionary

이 부분은 문제를 보고 바로 이해하지 못해서  
Dictionary의 구조부터 다시 확인했다.

```python
d = {"a": 1, "b": 2}

d["c"] = 3
d["a"] = 10

print(len(d), sum(d.values()))
```

처음 상태:

```text
a → 1
b → 2
```

```python
d["c"] = 3
```

`c`라는 Key가 없으므로 새 항목 추가.

```text
a → 1
b → 2
c → 3
```

그다음:

```python
d["a"] = 10
```

`a`는 이미 존재하므로  
새 항목을 만드는 것이 아니라 기존 값을 수정한다.

```text
a → 10
b → 2
c → 3
```

따라서:

```python
len(d)
```

→ Key 개수 `3`

```python
sum(d.values())
```

→ 값의 합

```text
10 + 2 + 3 = 15
```

결과:

```text
3 15
```

기억:

```text
없는 Key에 값 저장
→ 추가

있는 Key에 값 저장
→ 수정
```

# 1. Java

## continue

반복문 안에서 `continue`를 만나면  
현재 반복의 남은 코드를 건너뛰고 다음 반복으로 넘어간다.

```java
for (int i = 1; i <= 10; i++) {
    if (i % 3 == 0) continue;
    sum += i;
}
```

여기서는:

```text
3
6
9
```

가 3의 배수이므로 `sum += i`를 실행하지 않는다.

시험 재풀이에서는 이 문제를 맞혔다.

기억:

> **continue = 이번 반복의 아래쪽 코드를 Skip하고 다음 반복**

## Overriding / Polymorphism

```java
Parent p = new Child();
```

부모 타입 변수에 자식 객체를 넣을 수 있다.

자식 클래스가 부모의 Method를 Override했다면  
호출되는 Method는 **실제 생성된 객체**를 기준으로 결정된다.

예:

```java
Parent p = new Child();
p.show();
```

실제 객체:

```text
Child
```

따라서 `Child`의 `show()`가 실행된다.

재풀이에서도:

```text
Parent p = new Child()
→ C

Parent q = new Parent()
→ P
```

를 구분해서 `CP`를 맞혔다.

기억:

```text
변수 Type
vs
실제 Object

Override Method 호출
→ 실제 Object를 본다
```

# 3. Operating System

## Process 상태 전이

### Dispatch

```text
Ready
 ↓
Running
```

준비 상태의 Process가 CPU를 할당받아  
실행 상태가 되는 것.

```text
Ready → Running
= Dispatch
```

같이 구분한 상태 전이:

```text
Running → Ready
= Timeout

Running → Waiting
= Block

Waiting → Ready
= Wake Up
```

---

# Scheduling

Scheduling은 여러 Process 중  
누구에게 CPU를 할당할지 결정하는 방식이다.

## 비선점형

시험문제에서:

```text
FCFS
SJF
HRN
```

은 비선점형으로 구분했다.

## 선점형

```text
Round Robin
```

은 선점형이다.

실행 중인 Process가 있어도  
정해진 CPU 사용 시간이 끝나면 다른 Process에게 CPU를 넘길 수 있다.

기억:

> **Round Robin = 선점형**

---

## HRN

HRN의 우선순위 공식:

```text
(대기시간 + 서비스시간) ÷ 서비스시간
```

계산한 값이 **가장 큰 Process가 먼저 실행**된다.

예:

```text
대기시간 = 6
서비스시간 = 2

(6 + 2) ÷ 2
= 4
```

기억:

> **HRN = (대기 + 서비스) / 서비스 → 큰 값 먼저**

---

# Deadlock

교착상태.

여러 Process가 서로 상대방이 가지고 있는 자원을 기다리면서  
아무도 진행하지 못하는 상황이다.

Deadlock 발생 필요조건:

```text
상호 배제
점유와 대기
비선점
환형 대기
```

암기:

```text
상 · 점 · 비 · 환
```

문제에서 주의할 부분:

```text
선점
→ Deadlock 필요조건 X

비선점
→ Deadlock 필요조건 O
```

---

## Banker Algorithm

Banker's Algorithm은 Deadlock이 발생한 뒤 해결하는 것이 아니라  
자원을 할당하기 전에 안전한 상태인지 확인한다.

즉:

```text
Banker Algorithm
→ Deadlock Avoidance
→ 교착상태 회피
```

기억:

> **은행원이 돈을 빌려주기 전에 안전한지 확인한다 → 회피**

---

## Best Fit

빈 메모리 공간 중  
프로그램이 들어갈 수 있으면서 **남는 공간이 가장 작은 곳**을 선택한다.

예:

```text
프로그램 = 10K

5K  → 불가능
14K → 4K 남음
10K → 0K 남음
12K → 2K 남음
```

따라서:

```text
Best Fit
→ 10K
```

기억:

> **Best Fit = 가장 딱 맞는 공간**

같이 구분:

```text
First Fit
→ 처음 들어갈 수 있는 공간

Best Fit
→ 가장 딱 맞는 공간

Worst Fit
→ 가장 큰 공간
```

---

## Thrashing

Page 교체가 너무 자주 발생해서  
실제 작업보다 Page 교체에 더 많은 시간을 쓰는 현상.

기억:

> **페이지 교체 지옥**

시험 보기에서 함께 구분한 개념:

```text
서로 자원을 기다리며 멈춤
→ Deadlock

우선순위가 낮은 Process가 계속 CPU를 받지 못함
→ Starvation

작은 빈 메모리 공간이 발생
→ Fragmentation

Page 교체를 지나치게 반복
→ Thrashing
```

# 정규형 NF

`NF`는:

```text
Normal Form
→ 정규형
```

정규화 단계:

```text
1NF
→ 원자값

2NF
→ 부분 함수 종속 제거
```

정답:

```text

```

## GROUP BY / AVG / HAVING

```sql

FROM 사원

HAVING AVG(급여) >= 300;
```

순서대로:

```text
GROUP BY
→ 부서별로 묶음

AVG
→ 부서별 평균 계산

HAVING
→ 묶은 결과에 조건 적용
```

예:

```text

영업 평균 = 250
인사 평균 = 400
```

```text
AVG >= 300
```

을 만족:

```text
개발
인사
```

총 2개.

기억:

```text
WHERE
→ Grouping 전 조건

HAVING
→ Grouping 후 조건
```

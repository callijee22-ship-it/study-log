# 1. Java

## continue

반복문 안에서 `continue`를 만나면  
현재 반복의 남은 코드를 건너뛰고 다음 반복으로 넘어간다.

```text
현재 반복
   ↓
continue
   ↓
나머지 코드 Skip
   ↓
다음 반복
```

---

## Overriding / Polymorphism

```java
Parent p = new Child();
```

부모 타입 변수에 자식 객체를 넣을 수 있고,  
Override된 Method가 있다면 실제 객체의 Method가 실행된다.

복습하면서:

```text
변수 Type
vs
실제 생성된 Object
```

를 구분해서 봐야 했다.

---

## == 와 equals()

String 비교에서 다시 헷갈렸던 부분.

```java
String a = "java";
String b = new String("java");
```

```java
a == b
```

→ 같은 객체인지 비교

```java
a.equals(b)
```

→ 문자열 내용이 같은지 비교

즉:

```text
==
→ Reference 비교

.equals()
→ 내용 비교
```

# 3. Operating System

## Dispatch

Process 상태 전이:

```text
Ready
  ↓
Running
```

으로 바뀌는 과정을 **Dispatch**라고 한다.

---

## Round Robin

Round Robin Scheduling은  
각 Process에 일정한 Time Quantum을 주면서 번갈아 실행한다.

복습 포인트:

> **Round Robin = Preemptive Scheduling**

---

## HRN

Scheduling Algorithm 중 하나로  
대기 시간과 실행 시간을 이용해 우선순위를 계산한다.

이날은 이름과 Scheduling 유형을 다시 구분하는 수준으로 복습했다.

---

## Deadlock

Deadlock 관련 조건들도 다시 확인했다.

핵심은:

> 여러 조건이 동시에 만족되면 Deadlock이 발생할 수 있다.

---

## Banker Algorithm

Banker Algorithm은 Deadlock을

```text
발생 후 해결
```

하는 방식이 아니라

```text
발생하지 않도록 미리 판단
```

하는 방식이다.

즉:

> **Deadlock Avoidance**

---

## Thrashing

Page 교체가 지나치게 많이 발생해서  
실제 작업보다 Page 교체에 시간을 대부분 쓰는 상태.

내가 기억한 방식:

> **페이지 교체 지옥**

---

## Best Fit

Memory Allocation 방식 중  
Process가 들어갈 수 있는 공간 중 가장 작은 공간을 선택하는 방식.

---

# 4. Linux

## chmod 754

Linux Permission 숫자 계산을 다시 복습했다.

```text
r = 4
w = 2
x = 1
```

따라서:

```text
7 = rwx
5 = r-x
4 = r--
```

```bash
chmod 754
```

는:

```text
Owner
→ rwx

Group
→ r-x

Others
→ r--
```

# 5. Database / SQL

## Cardinality

Table에서 **행(Row)의 개수**를 의미한다.

```text
Cardinality
→ Row 수
```

---

## 2NF

Second Normal Form.

정규화 단계 중 하나로  
부분 함수 종속을 제거하는 것과 관련된 개념을 복습했다.

---

## GRANT

사용자에게 권한을 부여할 때 사용한다.

```sql
GRANT
```

---

## DROP

Database Object 자체를 삭제할 때 사용한다.

```sql
DROP
```

---

## DESC

Table 구조를 확인할 때 사용한다.

```sql
DESC table_name;
```

---

## HAVING

GROUP BY 결과에 조건을 줄 때 사용한다.

```text
WHERE
→ Grouping 전 조건

HAVING
→ Grouping 후 조건
```

---

## INNER JOIN

두 Table에서  
조건이 일치하는 데이터만 가져오는 JOIN.

```text
Table A
   ∩
Table B
```

처럼 겹치는 부분을 가져온다고 이해했다.

## == 와 equals()

String 비교에서 다시 헷갈렸던 부분.

```java
String a = "java";
String b = new String("java");
```

```java
a == b
```

→ 같은 객체인지 비교

```java
a.equals(b)
```

→ 문자열 내용이 같은지 비교

즉:

```text
==
→ Reference 비교

.equals()
→ 내용 비교
```

## Round Robin

Round Robin Scheduling은  
각 Process에 일정한 Time Quantum을 주면서 번갈아 실행한다.

복습 포인트:

> **Round Robin = Preemptive Scheduling**

---

## HRN

Scheduling Algorithm 중 하나로  
대기 시간과 실행 시간을 이용해 우선순위를 계산한다.

HRN = (대기 + 서비스) ÷ 서비스

ex))
대기시간 = 6
서비스시간 = 2

(6 + 2) ÷ 2
= 8 ÷ 2
= 4

이날은 이름과 Scheduling 유형(선점형/비선점형)을 다시 구분하는 수준으로 복습했다.
-비선점형 : 한 프로세스가  CPU를 잡으면, 보통 자기 작업이 끝나거나 스스로 놓을 때까지 사융
ㄴFCFS(First Come First Served) : 먼저 온 프로세스를 먼저 실행 = 선착순
ㄴSJF(Shortest Job First) : 실행 시간이 가장 짧은 작업부터 먼저 실행
ㄴHRN(Highest Response-ratio Next) : 대기시간과 서비스 시간을 같이 계산해서 값이 가장 높은 작업부터 실행

-선점형 : 실행 중이어도 운영체제가 CPU를 중간에 뺏어서 다른 프로세스에게 줄 수 있음
ㄴRound Robin : 각 프로세스에 정해진 시간만큼만 CPU분배

## Deadlock 교착상태 : 서로 자원을 기다리며 멈춘 상태

Deadlock 관련 조건들도 다시 확인했다.
ㄴ상호배제.점유와대기.비선점.환형대기 조건으로 발생되는 상황.

핵심은:

> 여러 조건이 동시에 만족되면 Deadlock이 발생할 수 있다.

*Thrashing
페이지교체가 너무 자주 일어나서 실제 작업보다 페이지 교체에 더 많은 시간을 쓰는 현상
ㄴ메모리는 부족한테 많은 프로세스를 동시에 돌리려고 할 때 발생

*Stavation
기아상태 : 특정 프로세스가 CPU나 자원을 계속 할당받지 못하는 상태
ㄴ우선순위 높은 작업부터 처리하는 방식으로 우선순위가 낮은것은 지속적으로 처리되지 않는 상태

*Fragmentation
단편화 : 사용하지 못하는 빈공간이 생기는 상태
ㄴ주기억장치에 사용하지 못하는 작은 빈 공간이 생기는 현상

---

## Banker Algorithm

Banker Algorithm은 Deadlock을

```text
발생 후 해결
```

하는 방식이 아니라

```text
발생하지 않도록 미리 판단
```

하는 방식이다.

즉:

> **Deadlock Avoidance**

---

내가 기억한 방식:

> **페이지 교체 지옥**

# 4. Linux

## chmod 754

Linux Permission 숫자 계산을 다시 복습했다.

```text
r = 4
w = 2
x = 1
```

따라서:

```text
7 = rwx
5 = r-x
4 = r--
```

```bash
chmod 754
```

는:

```text
Owner
→ rwx

Group
→ r-x

Others
→ r--
```

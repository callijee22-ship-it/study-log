## continue

`continue`를 만나면 현재 반복의 남은 코드를 건너뛰고 다음 반복으로 넘어간다.

```java
for (int i = 1; i <= 10; i++) {
    if (i % 3 == 0) continue;
    sum += i;
}
```

여기서는:

```text
3
6
9
```

가 3의 배수이므로 `sum += i`를 실행하지 않는다.

### 이해 상태

```text
정답
→ 맞음

개념
→ continue가 현재 반복의 아래 코드를 Skip한다는 점 이해
```

## String `==` vs `.equals()`

이 부분은 **처음에는 문제 자체를 이해하지 못했다.**

```java
String a = "java";
String b = new String("java");

System.out.println((a == b) + " " + a.equals(b));
```

처음 막힌 부분:

```text
a == b
a.equals(b)

둘이 왜 다른지 모르겠음
```

다시 설명:

```text
==
→ 같은 객체를 가리키는지 비교

.equals()
→ 문자열 내용이 같은지 비교
```

`new String("java")`는 별도 객체를 만들기 때문에:

```text
a == b
→ false

a.equals(b)
→ true
```

결과:

```text
false true
```

---

## 문자열에서 `+`

이 부분도 따로 질문했다.

```java
(a == b) + " " + a.equals(b)
```

처음에는 `+`가 왜 들어가는지 이해하지 못했다.

문자열 `" "`가 포함되어 있으므로 여기서 `+`는 숫자 덧셈이 아니라 문자열 연결이다.

```text
false
+
" "
+
true

→ "false true"
```

이 설명 뒤에는 "이해했어"라고 확인했다.

### 이해 상태

```text
처음
→ 문제 자체가 이해되지 않음

재설명 후
→ == / .equals() 차이 이해
→ 문자열 + 연결 이해

상태
→ 설명 후 문제를 다시 풀 수 있게 됨
```

# 3. Operating System

## Process 상태 전이

### Dispatch

```text
Ready
 ↓
Running
```

준비 상태의 Process가 CPU를 할당받아 실행 상태가 되는 것.

```text
Ready → Running
= Dispatch
```

같이 구분:

```text
Running → Ready
= Timeout

Running → Waiting
= Block

Waiting → Ready
= Wake Up
```

### 이해 상태

```text
Dispatch
→ 다시 확인

상태 전이 전체
→ 용어를 함께 비교하며 복습한 상태
```

## HRN

HRN 우선순위 공식:

```text
(대기시간 + 서비스시간) ÷ 서비스시간
```

값이 큰 Process가 먼저 실행된다.

예:

```text
대기시간 = 6
서비스시간 = 2

(6 + 2) ÷ 2
= 4
```

### 이해 상태

```text
공식
→ 다시 확인

상태
→ 공식을 외우는 것보다 실제 계산을 반복할 필요 있음
```

## Deadlock

여러 Process가 서로 상대방의 자원을 기다리면서 진행하지 못하는 상태다.

Deadlock 필요조건:

```text
상호 배제
점유와 대기
비선점
환형 대기
```

암기:

```text
상 · 점 · 비 · 환
```

특히:

```text
선점
→ 필요조건 X

비선점
→ 필요조건 O
```

를 구분해야 한다.

### 이해 상태

```text
조건 4개
→ 다시 정리

주의
→ 선점 / 비선점 표현을 헷갈리지 않기
```

---

## Banker Algorithm

Banker's Algorithm은 Deadlock이 발생한 뒤 해결하는 방식이 아니라  
자원을 할당하기 전에 안전한지 확인하는 방식이다.

```text
Banker Algorithm
→ Deadlock Avoidance
→ 교착상태 회피
```

기억:

```text
은행원이 돈을 빌려주기 전에
안전한지 먼저 확인
→ 회피
```

## Best Fit

프로그램이 들어갈 수 있는 빈 공간 중 남는 공간이 가장 작은 곳을 선택한다.

예:

```text
프로그램 = 10K

5K  → 불가능
14K → 4K 남음
10K → 0K 남음
12K → 2K 남음

Best Fit
→ 10K
```

비교:

```text
First Fit
→ 처음 들어갈 수 있는 공간

Best Fit
→ 가장 딱 맞는 공간

Worst Fit
→ 가장 큰 공간
```

---

## Thrashing

Page 교체가 지나치게 자주 발생해서 실제 작업보다 Page 교체에 시간을 더 많이 쓰는 현상이다.

```text
Thrashing
→ 페이지 교체 지옥
```

같이 구분:

```text
서로 자원을 기다리며 멈춤
→ Deadlock

낮은 우선순위 Process가 계속 CPU를 못 받음
→ Starvation

작은 빈 메모리 공간이 생김
→ Fragmentation

Page 교체를 지나치게 반복
→ Thrashing
```

### 이해 상태

```text
개별 정의
→ 다시 구분

복습 필요
→ Deadlock / Starvation / Fragmentation / Thrashing을 보기에서 구분
```

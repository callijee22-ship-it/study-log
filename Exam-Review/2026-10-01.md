# Memory Allocation(메모리 할당)

프로세스를 메모리의 어느 빈 공간에 넣을지 결정하는 방식.

대표적으로:

```text
First Fit(최초 적합)
Best Fit(최적 적합)
Worst Fit(최악 적합)
```

을 다시 구분했다.

---

## First Fit(최초 적합)

프로세스가 들어갈 수 있는 공간을  
앞에서부터 찾다가 **처음 발견한 공간**에 넣는다.

```text
First
→ 처음

First Fit
→ 처음 들어갈 수 있는 곳
```

---

## Best Fit(최적 적합)

프로세스가 들어갈 수 있는 공간 중  
**남는 공간이 가장 작은 곳**을 선택한다.

예:

```text
프로세스 크기 = 10K

5K
→ 들어갈 수 없음

14K
→ 4K 남음

10K
→ 0K 남음

12K
→ 2K 남음
```

따라서:

```text
Best Fit
→ 10K
```

기억:

> **가장 딱 맞는 공간**

---

## Worst Fit(최악 적합)

들어갈 수 있는 공간 중  
**가장 큰 공간**을 선택한다.

```text
First Fit
→ 처음 발견

Best Fit
→ 가장 딱 맞음

Worst Fit
→ 가장 큰 공간
```

---

## 이해 상태

```text
First / Best / Worst Fit
→ 비교해서 다시 정리함

Best Fit
→ 문제 적용 가능

상태
→ 기본 차이는 이해
```

---

# NF(Normal Form, 정규형)

처음에는 `NF`라는 약어 자체도 다시 확인했다.

```text
NF
→ Normal Form
→ 정규형
```

정규화 단계:

```text
1NF
→ 원자값

2NF
→ 부분 함수 종속 제거

3NF
→ 이행 함수 종속 제거

4NF
→ 다치 종속 제거
```

암기:

```text
1 원자
2 부분
3 이행
4 다치
```

---

## 1NF(First Normal Form, 제1정규형)

핵심:

```text
한 칸에는 하나의 값
→ Atomic Value(원자값)
```

예를 들어 한 컬럼에:

```text
취미 = 게임, 영화, 운동
```

처럼 여러 값이 한꺼번에 들어 있다면  
원자값으로 보기 어렵다.

### 이해 상태

```text
1NF
→ 원자값

이 부분은 다시 질문한 뒤 개념 확인
```

---

## 2NF(Second Normal Form, 제2정규형)

```text
부분 함수 종속 제거
```

---

## 3NF(Third Normal Form, 제3정규형)

```text
이행 함수 종속 제거
```

---

## 4NF(Fourth Normal Form, 제4정규형)

```text
다치 종속 제거
```

# ☀️ 2. 오후 문제풀이

오후에는 시험 대비 범위의 문제를 빠르게 다시 풀었다.

# Cardinality(카디널리티) / Degree(차수)

```text
Cardinality(카디널리티)
→ Tuple(튜플) 수
→ Row(행) 수

Degree(차수)
→ Attribute(속성) 수
→ Column(열) 수
```

암기:

```text
Cardinality = 행
Degree = 열
```

문제를 풀다가 한 번 잘못 선택했지만  
다시 확인하면서 Row / Column 기준으로 정리했다.

---

# 2NF 다시 확인

문제에서:

> 1NF를 만족하는 Relation(릴레이션)을 2NF로 만들려면?

정답:

```text
부분 함수 종속 제거
```

다시 연결:

```text

```

# DESC(Descending, 내림차순)

`DESC`는 문맥에 따라 의미가 달라질 수 있다는 점을 다시 봤다.

정렬에서:

```sql
ORDER BY score DESC;
```

의 `DESC`는:

```text
Descending(내림차순)
→ 큰 값부터 작은 값 순서
```

예:

```text
100
90
80
70
```

반대:

```text
ASC
→ Ascending(오름차순)
```

주의:

```text
DESC table_name;
```

처럼 쓰면 `DESCRIBE`의 축약으로  
테이블 구조 확인을 의미할 수도 있다.

따라서:

> **문맥을 같이 봐야 한다.**

---

# INNER JOIN(내부 조인)

두 Table(테이블)의 Join Condition(조인 조건)이  
**일치하는 행만 가져오는 방식**이다.

```text
Table A
   ∩
Table B
```

처럼 공통으로 연결되는 데이터만 남긴다고 이해했다.

예:

```text
학생 학과코드 = 10
학과 학과코드 = 10
→ 포함

학생 학과코드 = NULL
→ 연결되는 값 없음
→ 제외
```

기억:

```text
INNER JOIN
→ 양쪽에서 짝이 맞는 것만
```

# ⏰ 3. 시험 직전 복습

시험 직전에는 새로운 내용을 많이 넣기보다  
전날과 오늘 문제에서 헷갈렸던 개념을 빠르게 반복했다.

---

# Deadlock(교착상태)

여러 Process(프로세스)가 서로 필요한 자원을 기다리면서  
아무도 진행하지 못하는 상태.

Deadlock 필요조건 4가지:

```text
상호 배제
점유와 대기
비선점
환형 대기
```

암기:

```text
상 · 점 · 비 · 환
```

특히 주의:

```text
선점
→ Deadlock 필요조건 X

비선점
→ Deadlock 필요조건 O
```

문제에서는 이 부분을 바로 구분했다.

### 이해 상태

```text
Deadlock 필요조건
→ 이해됨
```

---

# Banker's Algorithm(은행원 알고리즘)

Deadlock이 이미 발생한 뒤 해결하는 방식이 아니라  
자원을 할당하기 전에 **안전한 상태인지 확인**한다.

```text
Banker's Algorithm
→ Deadlock Avoidance(교착상태 회피)
```

기억:

> 은행원이 돈을 빌려주기 전에  
> 갚을 수 있는지 확인한다.

### 이해 상태

```text
Banker
→ Deadlock 회피

문제에서 바로 구분 가능
```

---

# Thrashing(스래싱)

Page(페이지) 교체가 너무 자주 발생해서  
실제 작업보다 페이지 교체에 더 많은 시간을 소비하는 현상.

```text
Thrashing
→ 페이지 교체 지옥
```

같이 구분:

```text
Deadlock(교착상태)
→ 서로 자원을 기다리며 멈춤

Starvation(기아 상태)
→ 특정 Process가 계속 자원을 얻지 못함

Fragmentation(단편화)
→ 메모리 공간이 조각남

Thrashing(스래싱)
→ Page 교체를 지나치게 반복
```

### 이해 상태

```text
Thrashing 문제
→ 바로 구분함
```

---

# Scheduling(스케줄링)

CPU를 어떤 Process에 배정할지 결정한다.

## Non-preemptive Scheduling(비선점형 스케줄링)

```text
FCFS
SJF
HRN
```

## Preemptive Scheduling(선점형 스케줄링)

```text
Round Robin(라운드 로빈)
```

---

# HRN(Highest Response-ratio Next)

우선순위:

```text
(대기시간 + 서비스시간) ÷ 서비스시간
```

값이 큰 Process가 먼저 실행된다.

예:

```text
대기시간 = 6
서비스시간 = 2

(6 + 2) ÷ 2
= 4
```

### 이해 상태

```text
공식 선택 문제
→ 정답

하지만 계산 문제는 반복 연습 필요
```

---

# Process State(프로세스 상태 전이)

```text
Ready → Running
= Dispatch(디스패치)

Running → Ready
= Timeout(타임아웃)

Running → Waiting
= Block(블록)

Waiting → Ready
= Wake Up(웨이크 업)
```

특히:

```text
Ready → Running
→ Dispatch
```

문제는 바로 맞혔다.

```text
CREATE
ALTER
DROP
```

Database Object(데이터베이스 객체)의 구조와 관련.

# DELETE / TRUNCATE / DROP

```text
DELETE
→ Row 삭제
→ Table 구조 유지

TRUNCATE
→ 모든 Row 삭제
→ Table 구조 유지

DROP
→ Table 자체 삭제

```

시험 직전 문제에서는:

```text
Table 구조까지 삭제

```

# WHERE / HAVING

```text
WHERE
→ Grouping(그룹화) 전 조건

HAVING
→ GROUP BY 이후 조건
```

예:

```sql
SELECT department
FROM employee
GROUP BY department
HAVING AVG(salary) >= 300;
```

흐름:

```text
부서별로 묶기
→ 평균 계산
→ 평균 300 이상인 그룹만 남기기
```

### 이해 상태

```text
HAVING 문제
→ 바로 맞힘
```

# Integrity(무결성)

시험 직전에 이 부분은 제대로 흔들렸다.

## Entity Integrity(개체 무결성)

```text
Primary Key(기본키)
→ NULL 불가
```

## Domain Integrity(도메인 무결성)

```text
컬럼에 들어가는 값은
정해진 범위 / 형식을 지켜야 함
```

예:

```text
점수
→ 0~100

나이
→ 정해진 숫자 범위
```

## Referential Integrity(참조 무결성)

```text
Foreign Key(외래키)
→ 올바른 참조 대상을 가리켜야 함
```

암기:

```text
개체 = PK
도메인 = 값의 범위
참조 = FK
```

### 이해 상태

```text
참조 무결성 문제
→ 개체 무결성 선택 ❌

도메인 무결성 문제
→ 개체 무결성 선택 ❌

상태
→ 시험 직전까지 세 개가 서로 섞였음
→ 추가 복습 필요
```

# Paging(페이징) / Segmentation(세그멘테이션)

시험 직전에 새로 다시 보려고 했지만  
Segmentation 개념이 바로 잡히지 않았다.

```text
Paging(페이징)
→ 고정 크기
→ 같은 크기로 나눔

Segmentation(세그멘테이션)
→ 논리적인 단위
→ 가변 크기
```

추가 연결:

```text
Paging
→ 내부 단편화 가능

Segmentation
→ 외부 단편화 가능
```

하지만 문제를 반복해서 풀었을 때도  
둘을 계속 반대로 선택했다.

그래서 시험 직전에는 더 붙잡지 않고:

> **시험 후 다시 공부할 항목**

으로 남겼다.

### 이해 상태

```text
Paging vs Segmentation
→ 미정착

시험 후 복습 필요
```

# ❌ 실제 오답 1 — Java String 비교

문제:

```java
String a = "java";
String b = new String("java");

System.out.println((a == b) + " " + a.equals(b));
```

내 선택:

```text
true false ❌
```

정답:

```text
false true ✅
```

---

## `==`

Java에서 객체에 `==`를 사용하면:

```text
같은 객체를 가리키는가?
```

를 본다.

```java
String b = new String("java");
```

는 새로운 String Object(문자열 객체)를 만든다.

따라서:

```text
a와 b의 문자열 내용
→ 같음

a와 b가 가리키는 객체
→ 다름
```

그래서:

```java
a == b
```

는:

```text
false
```

---

## `.equals()`

String의 `.equals()`는:

```text
문자열 내용이 같은가?
```

를 비교한다.

둘 다 `"java"`이므로:

```java
a.equals(b)
```

결과:

```text
true
```

---

## 다시 잡은 기준

```text
==
→ 객체 비교

.equals()
→ 내용 비교
```

### 이해 상태

```text
시험 전
→ 한번 설명을 들었지만 완전히 정착되지 않음

실제 시험
→ 오답

시험 후
→ 객체 비교와 문자열 내용 비교를 다시 정리

상태
→ 반드시 재복습할 개념
```

# ❌ 실제 오답 2 — ACID

문제:

> 트랜잭션의 연산이 모두 반영되거나  
> 하나도 반영되지 않아야 한다는 성질은?

내 선택:

```text
Consistency(일관성) ❌
```

정답:

```text
Atomicity(원자성) ✅
```

---

# ACID

```text
A = Atomicity(원자성)
C = Consistency(일관성)
I = Isolation(독립성)
D = Durability(지속성)
```

---

## Atomicity(원자성)

핵심:

```text
All or Nothing
→ 전부 성공 또는 전부 실패
```

예:

```text
A 계좌에서 10만원 출금
+
B 계좌에 10만원 입금
```

둘 중 하나만 실행되면 안 된다.

```text
둘 다 성공
또는
둘 다 취소
```

되어야 한다.

기억:

> **작업 단위가 중간에서 깨지면 안 된다.**

---

## Consistency(일관성)

트랜잭션 전후에도  
Database의 규칙과 무결성이 유지되어야 한다.

```text
Consistency
→ 규칙 유지
```

기억:

> **데이터 규칙이 깨지면 안 된다.**

---

## Isolation(독립성)

여러 Transaction(트랜잭션)이 동시에 실행되어도  
서로의 작업에 함부로 영향을 주지 않아야 한다.

```text
Isolation
→ 서로 간섭 X
```

---

## Durability(지속성)

Commit(커밋)이 완료된 결과는  
시스템에 문제가 생겨도 유지되어야 한다.

```text
Durability
→ 성공 결과 유지
```

---

## ACID 초압축

```text
Atomicity(원자성)
→ All or Nothing
→ 전부 또는 전무

Consistency(일관성)
→ DB 규칙 유지

Isolation(독립성)
→ 서로 간섭하지 않음

Durability(지속성)
→ Commit 결과 유지
```

### 이해 상태

```text
Atomicity vs Consistency
→ 실제 시험에서 혼동

시험 후

```

## OSI 7계층

```text
7 Application Layer
→ 응용 계층

6 Presentation Layer
→ 표현 계층

5 Session Layer
→ 세션 계층

4 Transport Layer
→ 전송 계층

3 Network Layer
→ 네트워크 계층

2 Data Link Layer
→ 데이터 링크 계층

1 Physical Layer
→ 물리 계층
```

시험용 핵심:

```text
Network Layer(네트워크 계층)
→ IP
→ Routing(경로 설정)

→ TCP / UDP

Data Link Layer(데이터 링크 계층)
→ MAC Address(MAC 주소)

Physical Layer(물리 계층)
→ Cable / Signal
→ 케이블 / 신호
```

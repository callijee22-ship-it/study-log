# ☁️ 2026-10-08 AWS Study

## 📌 오늘 진행한 범위

이날은 전날 Q62 다음부터 이어서 **Q63 ~ Q81**까지 진행했다.

중요한 점:

- 찍어서 맞힌 문제, 헷갈린 문제, 설명을 듣고 정리한 개념은 따로 표시한다.
- 이 문서는 나중에 다시 봤을 때 개념을 재학습할 수 있도록 정리한 복습용 기록이다.

# 1. Amazon Managed Service for Apache Flink

Streaming Data(스트리밍 데이터)를 실시간으로 처리할 때 사용하는 관리형 서비스다.

특히 일정 시간 단위로 데이터를 묶어서 계산하는 **Window(윈도우)** 개념과 함께 나왔다.

예:

~~~text
최근 5분 동안 들어온 이벤트 수
최근 10분 평균값
시간 구간별 집계
~~~

### 현재 상태

Q63에서 이 개념을 거의 모르는 상태에서 답을 찍었다.

따라서:

~~~text
정답 여부
≠ 이해 완료
~~~

Flink와 Window 계산은 반복 학습 필요.

---

# 2. Streaming Window

실시간으로 계속 들어오는 데이터를
일정 시간 구간으로 잘라서 집계하는 방식이다.

예:

~~~text
10:00 ~ 10:05
10:05 ~ 10:10
10:10 ~ 10:15
~~~

각 구간마다 합계, 평균, 건수 등을 계산할 수 있다.

### 기억 포인트

~~~text
실시간 스트리밍
+
최근 N분 집계
→ Window
~~~

---

# 3. Parquet

Columnar Format(열 기반 저장 형식).

분석 쿼리에서 필요한 열만 읽기 쉬워
대규모 데이터 분석에 자주 사용된다.

### 특징

~~~text
열 기반 저장
압축 효율
분석 쿼리에 유리
Athena / Glue / Redshift Spectrum 등과 자주 연결
~~~

### 현재 상태

이미 여러 번 봤던 개념이지만
다른 포맷과 비교해서 문제를 풀 수 있는지 계속 확인 필요.

---

# 4. DynamoDB GSI

GSI = Global Secondary Index(글로벌 보조 인덱스)

기본 Primary Key(기본 키)가 아닌 다른 속성으로도
빠르게 조회할 수 있도록 인덱스를 추가한다.

~~~text
기본 Key 말고
다른 Column 기준 조회 필요
→ GSI
~~~

---

# 5. DynamoDB TTL

TTL = Time To Live.

지정한 시간이 지나면 오래된 Item을 자동으로 만료시키는 기능이다.

~~~text
임시 데이터
세션 데이터
일정 시간 후 자동 삭제
→ TTL
~~~

---

# 6. DynamoDB PITR

PITR = Point-in-Time Recovery(시점 복구)

특정 시점의 상태로 DynamoDB Table을 복구할 수 있게 한다.

~~~text
실수로 데이터 삭제/변경
→ 과거 특정 시점 복구
→ PITR
~~~

### GSI / TTL / PITR 구분

~~~text
다른 기준으로 빠르게 조회
→ GSI

시간 지나면 자동 만료
→ TTL

과거 특정 시점으로 복구
→ PITR
~~~

---

# 7. AWS Glue Job Bookmark

Glue ETL Job이 이전에 처리한 데이터를 기억해서
다음 실행 때 이미 처리한 데이터를 다시 읽지 않도록 돕는다.

~~~text
이전 처리 위치 기억
→ 다음 실행에서 새 데이터 중심 처리
→ Job Bookmark
~~~

### 문제 단서

~~~text
중복 처리 방지
이전에 처리한 데이터 기억
증분 처리
~~~

---

# 8. Dead-Letter Queue(DLQ)

정상적으로 처리되지 못한 메시지를
따로 모아두는 Queue(큐)다.

~~~text
메시지 처리 반복 실패
→ 버리지 않고 별도 보관
→ DLQ
~~~

나중에 실패 원인을 확인하거나 다시 처리할 수 있다.

---

# 9. VPC Gateway Endpoint

S3 같은 AWS 서비스에
인터넷이나 NAT Gateway를 통하지 않고
VPC 내부에서 사설로 접근할 수 있게 한다.

이날 문제에서는 **S3 + Gateway Endpoint** 조합으로 봤다.

~~~text
VPC
→ Gateway Endpoint
→ S3
~~~

---

# 10. Interface Endpoint / AWS PrivateLink

PrivateLink를 이용해서
지원되는 AWS 서비스에 사설 IP 기반으로 접근하게 한다.

~~~text
인터넷 없이
VPC 내부에서
서비스에 사설 접근
→ Interface Endpoint
~~~

### Gateway Endpoint와 구분

~~~text
S3 접근
→ Gateway Endpoint

PrivateLink 기반 사설 서비스 접근
→ Interface Endpoint
~~~

### 현재 상태

Q73~Q74 범위에서 확인한 내용.
Endpoint 종류 구분은 반복 필요.

---

# 11. S3 Storage Lens

S3 전체 사용 현황과 저장소 상태를
분석하고 시각화하는 기능이다.

~~~text
S3 사용량
스토리지 현황
조직/계정 단위 분석
→ Storage Lens
~~~

### S3 Inventory와 구분

S3 Inventory는 객체 목록과 메타데이터를
정기적으로 파일 형태로 만들어 주는 기능이다.

~~~text
S3 전체 사용 현황 분석
→ Storage Lens

Object 목록/메타데이터 보고서
→ S3 Inventory
~~~

### 현재 상태

이날 두 개를 처음에 헷갈렸다가 다시 정리했다.
따라서 반복 필요.

---

# 12. Redshift VACUUM

Redshift Table에서
삭제/업데이트 이후 남은 공간과 정렬 상태를 정리한다.

~~~text
데이터 정렬 재정비
공간 정리
→ VACUUM
~~~

---

# 13. Redshift ANALYZE

Query Optimizer(쿼리 최적화기)가
더 좋은 실행 계획을 만들 수 있도록
Table 통계 정보를 갱신한다.

~~~text
통계 정보 갱신
→ ANALYZE
~~~

### VACUUM vs ANALYZE

~~~text
데이터 물리 정리 / 정렬
→ VACUUM

통계 정보 갱신
→ ANALYZE
~~~

### 현재 상태

처음에는 두 개가 섞였고,
뒤 문제에서 다시 구분하면서 회복했다.

완전 정착으로 보지는 않는다.

---

# 14. Redshift UNLOAD

Redshift Query 결과를
S3 같은 외부 저장소로 내보낼 때 사용한다.

~~~text
Redshift
→ Query 결과
→ S3
→ UNLOAD
~~~

Q80에서는 이 개념을 문제에서 다시 확인했다.

---

# 15. SQL Window Function

행을 완전히 하나로 합치지 않고
현재 행과 관련된 여러 행을 기준으로 계산하는 함수다.

예:

~~~sql
SUM(amount) OVER (
  PARTITION BY customer_id
  ORDER BY ordered_at
)
~~~

이런 식으로 그룹별 누적합 등을 구할 수 있다.

### 기억 포인트

~~~text
GROUP BY
→ 여러 행을 그룹 결과 한 행으로 줄이는 경우가 많음

Window Function
→ 원래 행을 유지하면서 순위/누적합/평균 등을 계산
~~~

Q81에서는 Window Function 문제를 맞혔다.

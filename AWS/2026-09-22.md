# 🔗 데이터 파이프라인 기본 흐름

데이터 파이프라인은 데이터를 가져와서  
저장하고, 필요한 형태로 바꾸고, 최종적으로 사용하는 흐름이다.

오늘은 크게 다음 순서로 이해했다.

```text
수집
 ↓
저장
 ↓
변환
 ↓
소비
```

AWS 서비스와 연결하면:

```text
Kinesis
   ↓
S3
   ↓
Glue
   ↓
Athena
```

### ⭐ 한 줄로 기억하기

```text
Kinesis = 받기
S3 = 저장하기
Glue = 다듬기
Athena = 보기
```

---

# 📥 1. 데이터 수집

## Amazon Kinesis

Kinesis는 실시간으로 들어오는 데이터를  
수집하고 처리할 때 사용하는 서비스이다.

예를 들면:

```text
사용자 행동 데이터
센서 데이터
로그 데이터
실시간 이벤트
        ↓
     Kinesis
```

오늘은 세부 기능을 모두 외우기보다

> **Kinesis = 실시간 데이터가 들어오는 입구**

라고 먼저 기억하기로 했다.

### ⭐ 기억하기

```text
Kinesis = 실시간 데이터 수집
```

---

# 🪣 2. 데이터 저장

## Amazon S3

수집한 데이터를 저장할 수 있는 서비스이다.

앞에서 공부했던 내용과 연결해서  
S3는 AWS 데이터 파이프라인에서도 중요한 저장 공간으로 사용된다는 것을 다시 확인했다.

```text
데이터 수집
    ↓
   S3
    ↓
데이터 저장
```

### ⭐ 기억하기

```text
S3 = 데이터 저장
```

---

# 🧹 3. 데이터 변환

## AWS Glue

저장된 데이터를  
분석에 사용할 수 있도록 정리하고 변환하는 역할을 한다.

이 과정에서 ETL이라는 개념을 다시 공부했다.

---

## 🔄 ETL

```text
Extract
Transform
Load
```

### Extract

필요한 데이터를 가져온다.

### Transform

데이터를 원하는 형태로 정리하거나 변환한다.

### Load

변환한 데이터를 사용할 장소에 적재한다.

### 내가 이해한 방식

```text
데이터 가져오기
      ↓
데이터 다듬기
      ↓
필요한 곳에 넣기
```

### ⭐ 기억하기

```text
ETL = 가져오기 → 바꾸기 → 넣기
```

---

# 🔁 ETL과 ELT

ETL과 비슷한 개념으로 ELT도 같이 공부했다.

### ETL

```text
Extract
   ↓
Transform
   ↓
Load
```

먼저 데이터를 변환한 뒤 적재한다.

### ELT

```text
Extract
   ↓
Load
   ↓
Transform
```

먼저 데이터를 저장하고  
필요할 때 변환한다.

### ⭐ 구분하기

```text
ETL = 변환하고 저장

ELT = 저장하고 변환
```

---

# 🔍 4. 데이터 사용

## Amazon Athena

S3에 저장된 데이터를  
SQL을 이용해서 조회할 수 있는 서비스이다.

오늘 공부한 전체 흐름에서  
최종적으로 데이터를 확인하거나 분석하는 역할로 연결했다.

```text
S3
 ↓
Athena
 ↓
SQL Query
```

### ⭐ 기억하기

```text
Athena = S3 데이터를 SQL로 조회
```

---

# 🚦 Orchestration

데이터 파이프라인에는  
여러 작업을 **정해진 순서대로 실행하고 관리하는 과정**도 필요하다.

이를 Orchestration이라고 배웠다.

예를 들면:

```text
데이터 수집 완료
      ↓
저장
      ↓
변환 작업 실행
      ↓
분석 시작
```

이 과정들이 아무 순서로나 실행되는 것이 아니라  
앞 작업이 끝났는지 확인하면서 다음 작업을 실행해야 한다.

### 💡 내가 이해한 방식

```text
Orchestration
= 여러 작업의 실행 순서와 흐름 관리
```

---

# 🔐 Governance

데이터를 단순히 저장하는 것뿐 아니라  
누가 데이터를 사용할 수 있는지,  
어떻게 관리할 것인지도 중요하다.

이런 데이터 관리 체계를 Governance라고 배웠다.

### 내가 이해한 방식

```text
데이터가 있다
    ↓
누가 사용할 수 있지?
    ↓
어떻게 관리하지?
    ↓
어떤 규칙을 지켜야 하지?
```

### ⭐ 기억하기

```text
Governance = 데이터 관리 규칙
```

---

# 🔁 실패했을 때 다시 실행하기

데이터 처리 작업은 항상 성공하는 것이 아니기 때문에  
실패했을 때 다시 실행하는 방법도 중요하다.

오늘은 다음 개념들을 같이 봤다.

- Retry
- Checkpoint
- Idempotency
- DLQ

---

## 🔄 Retry

작업이 실패했을 때  
다시 실행하는 방식이다.

```text
작업 실행
   ↓
실패
   ↓
Retry
   ↓
다시 실행
```

### ⭐ 기억하기

```text
Retry = 실패하면 재시도
```

---

## 📍 Checkpoint

작업을 어디까지 처리했는지 기록하는 개념이다.

처음부터 다시 시작하지 않고  
이전에 처리한 위치를 기준으로 작업을 이어갈 수 있다.

### 내가 이해한 방식

```text
1 → 2 → 3 → 4 → 실패
            ↑
       여기까지 기록

다시 실행
   ↓
4부터 이어서 처리
```

### ⭐ 기억하기

```text
Checkpoint = 어디까지 했는지 기억
```

---

## 🔁 Idempotency

같은 작업을 여러 번 실행해도  
결과가 달라지거나 중복되지 않도록 만드는 개념이다.

처음에는 단어가 어려웠지만  
다음처럼 이해했다.

```text
같은 작업을 다시 실행해도
결과는 안전하게 동일하게
```

### ⭐ 기억하기

```text
Idempotency = 여러 번 실행해도 결과가 안전하게 동일
```

---

## 📮 DLQ

DLQ는 **Dead Letter Queue**의 약자이다.

정상적으로 처리되지 못한 메시지를  
따로 보관하는 곳이라고 이해했다.

```text
메시지 처리
   ↓
계속 실패
   ↓
DLQ
   ↓
실패 메시지 따로 보관
```

### ⭐ 기억하기

```text
DLQ = 처리 실패 메시지 보관
```

---

# 🧩 오늘 공부한 전체 흐름

```text
실시간 데이터
      ↓
   Kinesis
      ↓
     S3
      ↓
    Glue
      ↓
   Athena
```

역할로 바꾸면:

```text
받기
 ↓
저장
 ↓
다듬기
 ↓
보기
```

그리고 이 파이프라인을 안정적으로 운영하려면:

```text
Orchestration
= 실행 순서 관리

Governance
= 데이터 관리 규칙

Retry
= 실패 시 재시도

Checkpoint
= 처리 위치 기록

Idempotency
= 다시 실행해도 중복 방지

DLQ
= 실패 데이터 따로 보관
```

## 🤔 오늘 헷갈리기 쉬웠던 부분

서비스 이름을 각각 외우려고 하면  
Kinesis, S3, Glue, Athena가 전부 따로 느껴졌다.

하지만 데이터가 이동하는 순서로 연결하니  
훨씬 이해하기 쉬웠다.

```text
Kinesis
= 데이터를 받는다

S3
= 데이터를 저장한다

Glue
= 데이터를 정리한다

Athena
= 데이터를 조회한다
```

그래서 앞으로도 AWS 서비스를 외울 때  
**서비스 이름보다 먼저 역할을 연결해서 기억하기로 했다.**

# 📱 오늘의 공부 방식

오늘은 오랫동안 책상에 앉아서 공부하기보다  
퇴근 후 지하철에서도 다시 볼 수 있도록  
긴 설명보다 핵심 흐름과 한 줄 암기를 중심으로 정리했다.

```text
서비스 이름
   ↓
무슨 역할?
   ↓
어디에 연결?
   ↓
문제에서는 어떻게 나올까?
```

```text
데이터 파이프라인

```

서비스 이름만 보고 답을 고르기보다

**“이 문제는 수집인가? 저장인가? 변환인가? 조회인가?”**

를 먼저 생각해보기로 했다.

# ☁️ 2026-09-30 AWS Study

## 📌 오늘의 기록

오늘은 AWS 서비스 중  
**이벤트 전달 / 워크플로우 / 데이터베이스 마이그레이션** 관련 서비스를 복습했다.

짧게 문제를 풀면서  
서비스 이름보다 역할을 구분하는 데 집중했다.

---

# 1. Amazon SNS

SNS는 하나의 메시지를 여러 구독자에게 전달할 수 있는 서비스다.

```text
Message
   ↓
SNS Topic
   ↓
여러 Subscriber에게 전달
```

내가 기억할 핵심:

> **한 번 발행해서 여러 곳에 전달**

즉 Fan-out 구조를 만들 때 사용할 수 있다.

---

# 2. Amazon EventBridge

EventBridge는 이벤트를 받아  
조건에 맞는 대상에게 전달하는 역할을 한다.

```text
Event 발생
   ↓
EventBridge
   ↓
Rule 확인
   ↓
조건에 맞는 Target 실행
```

SNS와 헷갈리지 않게:

```text
SNS
→ 메시지를 여러 구독자에게 전달

EventBridge
→ 이벤트 조건을 보고 어디로 보낼지 결정
```

---

# 3. AWS Step Functions

Step Functions는 여러 작업을  
정해진 순서대로 연결해서 실행하는 Workflow 서비스다.

```text
작업 A
 ↓
성공?
 ├─ YES → 작업 B
 └─ NO  → 실패 처리
```

즉 단순히 이벤트를 전달하는 서비스가 아니라

> **작업 순서와 성공 / 실패 흐름을 관리**

하는 역할이다.

---

# 4. SNS / EventBridge / Step Functions 비교

```text
SNS
→ 알림 / 메시지 전달

EventBridge
→ 이벤트 조건 기반 Routing

Step Functions
→ 여러 작업의 순서와 Workflow 관리
```

세 문제를 다시 풀어보면서  
이 세 서비스의 역할 차이를 복습했다.

---

# 5. AWS DMS

DMS는 Database Migration Service.

기존 데이터베이스를 AWS 또는 다른 데이터베이스로 옮길 때 사용한다.

핵심:

> **데이터를 이동한다.**

또한 마이그레이션 중 서비스 중단 시간을 줄이는 데 사용될 수 있다.

```text
기존 Database
      ↓
     DMS
      ↓
새 Database
```

---

# 6. AWS SCT

SCT는 Schema Conversion Tool.

서로 다른 데이터베이스 엔진 사이에서 이동할 때  
Schema를 변환하는 역할을 한다.

예를 들어:

```text
기존 DB Schema
      ↓
     SCT
      ↓
대상 DB에 맞는 Schema
```

---

# 7. DMS와 SCT 비교

이 둘은 같이 등장해서 헷갈리기 쉽다.

```text
DMS
→ 실제 Data 이동

SCT
→ Schema 변환
```

한 줄로 외우기:

> **DMS는 데이터를 옮기고, SCT는 구조를 바꾼다.**

---

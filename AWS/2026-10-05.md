# 1. IAM
## Identity and Access Management(자격 증명 및 접근 관리)

오늘 초반에는 IAM이 아직 잘 이해되지 않았다.

다시 다음 네 가지를 구분했다.

~~~text
IAM User(사용자)
IAM Group(그룹)
IAM Policy(정책)
IAM Role(역할)
~~~

---

## IAM User(사용자)

AWS를 사용하는 특정 사용자 계정이다.

~~~text
사람
→ User
~~~

---

## IAM Group(그룹)

여러 User를 묶어서  
공통 권한을 관리할 때 사용한다.

~~~text
여러 User
→ Group
~~~

---

## IAM Policy(정책)

무엇을 할 수 있고 없는지를 적어 놓은  
Permission Rule(권한 규칙)이다.

~~~text
Policy
→ 권한 내용
~~~

---

## IAM Role(역할)

특정 사용자에게 영구적으로 붙는 계정이 아니라  
AWS Service나 사용자가 필요할 때 맡아서 사용하는 권한 역할이다.

예:

~~~text
EC2
→ S3 접근 필요
→ IAM Role 사용
~~~

---

## 다시 구분

~~~text
User
→ 사용자

Group
→ 사용자 묶음

Policy
→ 권한 규칙

Role
→ 필요할 때 맡는 권한 역할
~~~

### 이해 상태

오늘 초반:

~~~text
IAM 아직 잘 이해 안 됨
~~~

상태였다.

설명을 다시 듣고 문제를 반복한 뒤에는  
IAM 구분 기준을 다시 잡았고, 오늘 후반에는 **IAM은 이해했다고 판단**했다.

다만 이전에도 여러 번 흔들렸던 영역이므로  
다음 복습에서 다시 맞히는지 확인할 필요가 있다.

---

# 2. AWS Lambda(람다)

Lambda는 Serverless Compute(서버리스 컴퓨팅) 서비스다.

서버를 직접 만들고 관리하지 않고  
특정 Event(이벤트)가 발생했을 때 Code(코드)를 실행할 수 있다.

예:

~~~text
S3 파일 업로드
→ Event 발생
→ Lambda 실행
~~~

---

## Lambda Function(람다 함수)

Lambda에 등록해서 실행하는 코드 단위를  
Lambda Function(람다 함수)이라고 한다.

~~~text
Function
→ 실행할 코드 묶음
~~~

---

## Event(이벤트)

Lambda가 실행되는 계기가 되는 사건이다.

예:

~~~text
S3 Object 업로드
API 요청
EventBridge Rule 실행
~~~

---

## "코드를 실행한다"는 의미

오늘 이 표현 자체가 잘 와닿지 않았다.

Lambda에서 코드를 실행한다는 것은:

~~~text
내가 서버를 직접 켜서 프로그램 실행
X

AWS가 필요한 실행 환경을 준비
→ 등록한 Function 코드를 실행
O
~~~

라는 구조다.

### 이해 상태

~~~text
Lambda Function 자체
"코드 실행"이라는 표현
AWS가 실행 환경을 준비한다는 구조
~~~

에서 혼란이 있었다.

오늘 설명을 들었지만  
**완전히 이해했다고 처리하지 않고 다시 볼 항목으로 남긴다.**

---

# 3. S3 Inventory / Batch Operations / Storage Lens

이전부터 반복했던 세 서비스를 다시 확인했다.

## S3 Inventory(인벤토리)

~~~text
객체 목록 / 상태 보고서
~~~

## S3 Batch Operations(배치 작업)

~~~text
많은 객체에 실제 작업 실행
~~~

## S3 Storage Lens(스토리지 렌즈)

~~~text
S3 사용량 / 패턴 분석 Dashboard(대시보드)
~~~

구분:

~~~text
무엇이 있나?
→ Inventory

여러 객체에 작업
→ Batch Operations

전체 사용 현황 분석
→ Storage Lens
~~~

### 이해 상태

오늘 문제에서는 대부분 잘 구분했다.

---

# 4. CloudWatch / CloudTrail / AWS Config

이전부터 많이 헷갈렸던 세 서비스를 다시 문제로 확인했다.

## Amazon CloudWatch(클라우드워치)

Metric(지표), Log(로그), Alarm(알람)을 이용해  
현재 상태를 Monitoring(모니터링)한다.

~~~text
CPU 사용률
Metric
Log
Alarm
→ CloudWatch
~~~

## AWS CloudTrail(클라우드트레일)

~~~text
누가
언제
어떤 API 작업을 했는지
→ 기록
~~~

## AWS Config(컨피그)

~~~text
Resource 설정이
어떻게 바뀌었는지
→ 구성 변경 기록
~~~

다시 구분:

~~~text
현재 상태 감시
→ CloudWatch

누가 무슨 행동
→ CloudTrail

설정이 어떻게 변경
→ Config
~~~

### 이해 상태

오늘 문제는 대부분 맞혔지만  
CloudWatch에서:

~~~text
감시한다
→ 조건을 만족하면 Alarm
~~~

으로 연결되는 부분은 잠시 헷갈렸다.

따라서 큰 구분은 회수했지만  
CloudWatch의 Alarm 동작 흐름은 다시 확인할 필요가 있다.

---

# 5. S3 Event Notifications vs EventBridge

## S3 Event Notifications(이벤트 알림)

~~~text
S3 이벤트 발생
→ 바로 특정 대상 실행 / 알림
~~~

## Amazon EventBridge(이벤트브리지)

~~~text
Event
→ Rule / Pattern 확인
→ 조건에 맞는 Target 실행
~~~

구분:

~~~text
단순 S3 이벤트 반응
→ Event Notifications

조건 / 규칙 기반 Event Routing(이벤트 라우팅)
→ EventBridge
~~~

### 이해 상태

오늘은 이 구분을 비교적 안정적으로 맞혔다.

---

# 6. DMS / DataSync / Snowball

## AWS DMS
### Database Migration Service(데이터베이스 마이그레이션 서비스)

~~~text
Database Data 이동
→ DMS
~~~

## AWS DataSync(데이터 동기화)

~~~text
File / NAS
→ Network 기반 동기화
~~~

## AWS Snowball

~~~text
매우 큰 데이터
+
Network 전송이 비효율적
→ 물리 장비로 이동
~~~

구분:

~~~text
DB
→ DMS

File / NAS
→ DataSync

초대용량 + 물리 전송
→ Snowball
~~~

### 이해 상태

이전보다 구분이 잘 됐다.

---

# 7. S3 Storage Class(스토리지 클래스)

오늘 S3의 저장 클래스도 다시 문제로 확인했다.

핵심은:

~~~text
접근 빈도
복구 시간
비용
~~~

에 따라 Storage Class(스토리지 클래스)를 고르는 것이다.

이전부터 자주 헷갈린:

~~~text
Intelligent-Tiering
Lifecycle
Standard-IA
Glacier 계열
~~~

도 다시 연결해서 봤다.

### 이해 상태

오늘 문제는 대체로 맞혔지만  
이 영역은 이름이 많고 조건이 비슷해서 반복 복습이 필요하다.

---

# 8. AWS Glue vs Amazon EMR

## AWS Glue

~~~text
Serverless ETL(서버리스 ETL)
→ 서버 / Cluster 관리 부담 적음
~~~

## Amazon EMR

~~~text
Spark / Hadoop
→ Cluster(클러스터)를 직접 활용하는 빅데이터 처리
~~~

구분:

~~~text
Serverless ETL
→ Glue

Spark / Hadoop + Cluster 제어
→ EMR
~~~

### 이해 상태

오늘 다시 비교했고, 이전보다 구분이 안정적이었다.

# 📊 오늘의 이해 상태

| 개념 | 상태 |
| --- | --- |
| IAM User / Group / Policy / Role | 처음 미이해 → 재설명 / 반복 후 이해 |
| Lambda Function / 코드 실행 | **여전히 헷갈림, 반복 필요** |

| Event Notifications / EventBridge | 비교적 안정적으로 구분 |
| DMS / DataSync / Snowball | 이전보다 구분 잘 됨 |
| S3 Storage Class | 문제는 풀었지만 반복 복습 필요 |
| Glue / EMR | 이전보다 구분 안정적 |

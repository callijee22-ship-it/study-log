# 1. Amazon S3 Tables

S3에서 Apache Iceberg Table을
관리형으로 운영할 수 있도록 제공되는 기능이다.

기존 S3 Object를 단순히 파일로 저장하는 것과 달리
Table 형태의 분석 데이터를 관리하는 데 초점이 있다.

~~~text
S3
+
Managed Apache Iceberg Table
→ S3 Tables
~~~

### 연결해서 기억할 것

~~~text
Apache Iceberg
→ Open Table Format

S3 Tables
→ S3에서 Iceberg Table을 관리형으로 운영
~~~

### 현재 상태

Q82에서 새로 다룬 범위.
한 번 본 수준이므로 세부 기능은 반복 필요.

---

# 2. Compaction(컴팩션)

작은 파일이 너무 많이 생기면
Query 성능과 관리 효율이 떨어질 수 있다.

Compaction은 작은 파일 여러 개를
더 큰 파일로 합쳐 정리하는 작업이다.

~~~text
Small Files 다수
→ Compaction
→ 더 큰 파일로 통합
~~~

### 왜 필요한가?

작은 파일이 지나치게 많으면:

~~~text
읽어야 할 파일 수 증가
메타데이터 처리 증가
Query 성능 저하 가능
~~~

그래서 파일을 적절한 크기로 합치는 작업이 필요하다.

### 현재 상태

Q83에서 정답을 맞혔고,
작은 파일 문제와 연결해 설명까지 했다.

다만 이후 다른 Table 최적화 기능과 함께 나오면 다시 확인한다.

---

# 3. Athena Partition Projection

Athena에서 Partition 정보를
Glue Data Catalog에 매번 실제 Partition으로 등록하지 않고,
규칙을 기반으로 계산해서 사용할 수 있게 한다.

예:

~~~text
날짜가 계속 늘어나는 데이터

2026/10/01
2026/10/02
2026/10/03
...
~~~

이런 구조에서
날짜 규칙을 미리 정의해서 Partition을 예측할 수 있다.

### 기억 포인트

~~~text
Partition 등록을 계속 반복하기 어려움
규칙 기반 Partition 계산
→ Partition Projection
~~~

### 현재 상태

Q84에서 문제를 풀었다.
이 개념을 완전히 이해했다고 처리하지 않고 복습 대상으로 남긴다.

---

# 4. Redshift Materialized View

복잡한 Query 결과를 미리 계산해서 저장해 두고,
반복 조회할 때 빠르게 사용할 수 있도록 하는 View다.

일반 View는 Query 정의만 저장하지만,
Materialized View는 결과를 실제로 저장한다.

~~~text
복잡한 집계 Query
반복 실행
→ 미리 결과 저장
→ Materialized View
~~~

### 일반 View와 구분

~~~text
View
→ Query 정의 저장

Materialized View
→ Query 결과를 저장
~~~

### 현재 상태

Q85에서 문제를 풀었다.
이날 기록만으로 이해 완료라고 보지 않고
일반 View와의 차이를 다시 설명해 보는 연습이 필요하다.

---

# 5. Redshift WLM

WLM = Workload Management(워크로드 관리)

Redshift에서 여러 Query가 동시에 실행될 때
작업 우선순위와 자원 사용을 관리하는 기능이다.

다만 이날은 **Q86을 실제로 풀기 전에 공부를 중단했다.**

따라서:

~~~text
WLM
→ 다음 학습 시작점
→ 이날 학습 완료로 기록하지 않음
~~~

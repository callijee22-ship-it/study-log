# ☁️ 2026-10-07 AWS Study

# 1. Redshift DISTSTYLE ALL

Redshift에서 작은 테이블의 전체 복사본을
각 Compute Node(컴퓨트 노드)에 두는 분산 방식이다.

~~~text
작은 Dimension Table
→ 모든 노드에 복제
→ JOIN 시 데이터 이동 감소
~~~

하지만 테이블이 크면 저장 공간과 로딩 비용이 커질 수 있다.

### 다시 볼 포인트

~~~text
DISTSTYLE ALL
→ 작은 테이블 전체 복제

DISTSTYLE KEY
→ 특정 Key 기준으로 분산
~~~

### 현재 상태

이날 문제 범위에서 다시 다뤘지만
ALL과 KEY를 자동으로 구분할 정도로 완전히 정착된 상태로 보지 않는다.

---

# 2. AWS Lake Formation

S3 기반 Data Lake(데이터 레이크)의
접근 권한을 중앙에서 관리하는 서비스다.

주로 다음과 연결해서 본다.

~~~text
Data Lake
Table / Column 권한
중앙 권한 관리
→ Lake Formation
~~~

### 현재 상태

IAM Policy, S3 Bucket Policy와 비슷하게
“권한 관리”라는 말이 같이 나와 헷갈릴 수 있다.

다음 복습에서는 다음을 따로 구분해야 한다.

~~~text
IAM Policy
→ IAM 사용자 / 역할 권한

S3 Bucket Policy
→ S3 리소스 정책

Lake Formation
→ Data Lake 세부 접근 제어
~~~

---

# 3. Amazon Macie

S3에 저장된 데이터에서
개인정보나 민감 정보를 탐지하는 서비스다.

~~~text
S3
+
PII / Sensitive Data(민감 데이터)
→ Amazon Macie
~~~

### 문제 단서

~~~text
개인정보
민감 정보
S3 데이터 분류
PII 탐지
~~~

---

# 4. Amazon GuardDuty

AWS 환경의 의심스러운 활동과
잠재적인 위협을 탐지하는 서비스다.

~~~text
이상 API 호출
의심스러운 접근
비정상 활동
→ GuardDuty
~~~

---

# 5. AWS Security Hub

여러 보안 서비스의 Finding(탐지 결과)을
한곳에 모아 확인하는 서비스다.

~~~text
Macie
GuardDuty
기타 보안 Finding
→ Security Hub에서 통합 확인
~~~

### 세 서비스 구분

~~~text
S3 민감정보
→ Macie

위협 / 이상 활동 탐지
→ GuardDuty

보안 결과 통합
→ Security Hub
~~~

### 현재 상태

세 서비스 모두 이날 반복해서 본 범위지만
아직 키워드만 보고 즉시 구분되는 수준이라고 기록하지 않는다.

---

# 6. AWS Glue Data Quality

데이터가 정해 둔 품질 조건을 만족하는지 검사한다.

예:

~~~text
NULL이 너무 많은가?
값 범위가 정상인가?
필수 Column이 존재하는가?
~~~

~~~text
Quality Rule(품질 규칙)
→ 데이터 검사
→ 품질 상태 확인
~~~

---

# 7. AWS Glue DataBrew

코드를 많이 작성하지 않고
데이터를 시각적으로 정리하고 변환하는 데 사용하는 도구다.

~~~text
값 정리
형식 변환
데이터 프로파일링
정제
→ DataBrew
~~~

### Data Quality와 구분

~~~text
데이터를 정리 / 변환
→ DataBrew

품질 규칙으로 검사
→ Glue Data Quality
~~~

### 현재 상태

이날 처음 넓게 본 범위에 가깝기 때문에
반복 문제를 통해 구분 연습이 필요하다.

---

# 8. S3 Policy / Encryption

S3 문제에서는
단순히 “접근 권한”인지 “암호화”인지 먼저 나눠서 봐야 한다.

## S3 Bucket Policy

Bucket 리소스에 직접 붙는 Resource-based Policy(리소스 기반 정책).

~~~text
특정 Principal 허용
특정 계정 접근
특정 조건에서만 접근
→ Bucket Policy
~~~

## Encryption(암호화)

S3 데이터가 저장될 때 암호화하는 방식이 문제로 나올 수 있다.

예:

~~~text
SSE-S3
SSE-KMS
~~~

SSE-KMS는 KMS Key를 이용하기 때문에
Key 사용 권한까지 같이 문제에 등장할 수 있다.

### 현재 상태

IAM / Bucket Policy / KMS 권한은 서로 섞이기 쉬워
추가 복습이 필요한 영역이다.

---

# 9. S3 Versioning

같은 Key의 객체가 변경되거나 삭제될 때
이전 버전을 남겨 복구할 수 있게 한다.

~~~text
실수로 덮어씀
실수로 삭제
→ 이전 Version 복구
→ Versioning
~~~

---

# 10. S3 Object Lock

객체를 일정 기간
삭제하거나 변경하지 못하도록 보호한다.

~~~text
WORM
규정 준수
보존 기간
삭제 방지
변경 방지
→ Object Lock
~~~

### Versioning과 구분

~~~text
이전 버전을 남김
→ Versioning

일정 기간 삭제 / 변경 자체를 막음
→ Object Lock
~~~

---

# 11. AWS DMS

Database Migration Service.

Database(데이터베이스)를
AWS 또는 다른 Database로 이전할 때 사용한다.

~~~text
DB 데이터 이동
→ DMS
~~~

---

# 12. CDC

Change Data Capture(변경 데이터 캡처).

처음 데이터를 옮긴 뒤
그 이후의 INSERT / UPDATE / DELETE 같은 변경분을 계속 따라간다.

~~~text
초기 데이터 이동
+
이후 변경분 지속 반영
→ CDC
~~~

DMS와 함께 자주 나온다.

---

# 13. AWS SCT

Schema Conversion Tool.

서로 다른 Database Engine 사이에서
Schema(스키마)를 변환할 때 사용한다.

~~~text
서로 다른 DB 엔진
+
Schema 변환
→ SCT
~~~

### DMS / CDC / SCT 구분

~~~text
실제 데이터 이동
→ DMS

변경분 지속 추적
→ CDC

서로 다른 엔진 간 Schema 변환
→ SCT
~~~

### 현재 상태

세 개를 한 묶음으로 다시 보는 것이 필요하다.

---

# 14. AWS Snowball

매우 큰 데이터를 네트워크로 옮기기 어려울 때
물리 장비를 이용해 AWS로 이전하는 방식이다.

~~~text
대용량
느린 네트워크
물리 장비
→ Snowball
~~~

---

# 15. AWS DataSync

On-premises Storage(온프레미스 스토리지)와
AWS Storage 사이에서 데이터를 자동으로 전송 / 동기화한다.

~~~text
온프레미스 파일
↔ S3 / EFS 등
자동 전송
→ DataSync
~~~

---

# 16. AWS Transfer Family

SFTP / FTPS / FTP 같은 파일 전송 프로토콜을
AWS에서 관리형으로 사용할 수 있게 한다.

~~~text
SFTP
FTPS
FTP
→ Transfer Family
~~~

---

# 17. Amazon AppFlow

SaaS 애플리케이션과 AWS 서비스 사이에서
데이터를 이동할 때 사용하는 관리형 서비스다.

~~~text
SaaS
↔ AWS
→ AppFlow
~~~

### 데이터 이동 서비스 비교

~~~text
물리 장비
→ Snowball

스토리지 간 자동 전송
→ DataSync

SFTP / FTPS / FTP
→ Transfer Family

SaaS ↔ AWS
→ AppFlow
~~~

### 현재 상태

서비스 이름이 많아
출발점과 전송 방식을 보고 구분하는 연습이 필요하다.

---

# 18. AWS Step Functions

여러 작업을 순서와 조건에 따라 연결하는
Workflow Orchestration(워크플로 오케스트레이션) 서비스다.

~~~text
Task
→ 다음 Task
→ 조건 분기
→ 실패 처리
~~~

Retry(재시도), Catch(실패 경로 처리) 같은 동작도 함께 연결된다.

---

# 19. AWS Glue Workflow

Glue Job, Crawler 같은
Glue 작업 중심의 실행 흐름을 관리한다.

~~~text
Crawler
→ Glue Job
→ 다음 Glue 작업
~~~

---

# 20. Amazon MWAA

Managed Workflows for Apache Airflow.

Apache Airflow를 AWS에서 관리형으로 사용할 수 있게 한다.

~~~text
Airflow DAG
→ MWAA
~~~

### Workflow 서비스 구분

~~~text
AWS 서비스 전반의 상태 기반 Workflow
→ Step Functions

Glue 작업 중심
→ Glue Workflow

Airflow DAG 기반
→ MWAA
~~~

### 현재 상태

세 서비스 모두 “작업 흐름”이라는 공통점이 있어
문제 문맥을 보고 구분하는 연습이 필요하다.

---

# 21. Apache Iceberg

대규모 분석 데이터를 위한
Open Table Format(오픈 테이블 형식)이다.

S3 같은 Object Storage 위의 데이터를
테이블처럼 관리하는 데 사용한다.

관련 개념:

~~~text
Schema Evolution
Partition 관리
대규모 분석 테이블
~~~

### 이날 실제 상태

Q62에서 Apache Iceberg 문제를 풀었고
**3번을 선택했다.**

다만 이 시점에는 이동 중이었고
“틀렸으면 개념만 짚어 달라”고 했기 때문에
이 개념을 완전히 이해했다고 기록하지 않는다.

~~~text
Apache Iceberg
→ 문제에서 한 번 확인
→ 세부 개념은 반복 필요
~~~

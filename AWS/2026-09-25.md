# 🌏 Region

Region은 AWS의 서비스가 운영되는  
**하나의 지리적인 지역**이다.

예를 들면:

```text
서울 Region
도쿄 Region
버지니아 Region
```

각 Region은 서로 떨어져 있다.

### ⭐ 기억하기

```text
Region = AWS의 큰 지역
```

---

# 🏢 Availability Zone

Availability Zone은  
하나의 Region 안에 존재하는  
**서로 독립된 물리적인 영역**이다.

하나의 Region 안에는  
여러 개의 AZ가 존재할 수 있다.

```text
Region
│
├── AZ 1
├── AZ 2
└── AZ 3
```

중요한 점은  
각 AZ가 물리적으로 분리되어 있다는 것이다.

한 AZ에 문제가 발생하더라도  
다른 AZ까지 같이 영향을 받지 않도록 설계된다.

### 💡 내가 이해한 방식

```text
Region = 큰 지역

AZ = 그 지역 안에서
     서로 떨어져 있는 서버 구역
```

### ⭐ 기억하기

```text
AZ = 장애를 분리하기 위한 독립 영역
```

---

# 🏗️ Multi-AZ

Multi-AZ는  
하나의 서비스나 시스템을  
여러 Availability Zone에 나누어 구성하는 방식이다.

예를 들어 한 AZ에 문제가 생기더라도  
다른 AZ에서 서비스를 계속 제공할 수 있다.

```text
        Region
          │
     ┌────┴────┐
     │         │
    AZ 1      AZ 2
     │         │
   서비스     서비스
```

### 💡 내가 이해한 방식

```text
한 군데만 사용
→ 그곳에 장애가 나면 위험

여러 AZ 사용
→ 한 곳에 문제가 생겨도 다른 곳 사용 가능
```

### ⭐ 기억하기

```text
Multi-AZ = 가용성을 높이기 위해 여러 AZ 사용
```

---

# 📈 Scalability

Scalability는  
사용량이 많아졌을 때

**시스템의 처리 능력을 확장할 수 있는 능력**이다.

예를 들면:

```text
사용자 증가
    ↓
현재 서버로 부족
    ↓
자원 추가
    ↓
더 많은 요청 처리
```

### ⭐ 기억하기

```text
Scalability = 확장할 수 있는 능력
```

---

# 🔁 Elasticity

Elasticity는  
필요에 따라 자원을 늘렸다가  
필요가 줄어들면 다시 줄이는 성질이다.

```text
사용량 증가
    ↓
자원 증가

사용량 감소
    ↓
자원 감소
```

### 🤔 Scalability와 차이

처음에는 두 단어가 비슷하게 느껴졌다.

```text
Scalability
= 확장이 가능한가?

Elasticity
= 상황에 맞게 늘었다 줄었다 할 수 있는가?
```

### ⭐ 기억하기

```text
Scalability = 확장 가능

Elasticity = 필요에 따라 자동으로 늘고 줄기
```

# 🔗 데이터 파이프라인

데이터가 만들어진 뒤  
최종적으로 사용되기까지의 전체 흐름을 다시 정리했다.

```text
수집
 ↓
저장
 ↓
처리 / 변환
 ↓
분석
 ↓
운영 / 보안
```

AWS 서비스 이름부터 외우기보다는  
먼저 이 흐름을 이해하는 데 집중했다.

---

## 1️⃣ 수집

데이터를 가져오는 단계이다.

예:

```text
사용자 로그
센서 데이터
애플리케이션 데이터
실시간 이벤트
```

이런 데이터가 AWS로 들어오는 과정이다.

---

## 2️⃣ 저장

수집한 데이터를 보관한다.

앞에서 공부했던 S3 같은 서비스가  
이 단계에 연결될 수 있다.

```text
수집한 데이터
     ↓
   저장
```

---

## 3️⃣ 처리 / 변환

저장된 데이터를  
분석하거나 사용하기 좋은 형태로 바꾼다.

```text
원본 데이터
     ↓
정리 / 변환
     ↓
사용 가능한 데이터
```

앞에서 공부했던 Glue도  
이 단계와 연결해서 기억했다.

---

## 4️⃣ 분석

정리된 데이터를 이용해서  
필요한 정보를 확인한다.

```text
정리된 데이터
     ↓
분석 / 조회
     ↓
필요한 정보 확인
```

Athena나 Redshift 같은 서비스가  
이 단계에서 사용될 수 있다.

---

## 5️⃣ 운영 / 보안

데이터를 처리하는 것뿐만 아니라

- 접근 권한
- 보안
- 장애 대응
- 시스템 운영

같은 부분도 함께 관리해야 한다.

### ⭐ 전체 흐름

```text
수집
 ↓
저장
 ↓
처리 / 변환
 ↓
분석
 ↓
운영 / 보안
```

# 📦 Batch Processing

Batch는 데이터를  
**일정량 모아두었다가 한 번에 처리하는 방식**이다.

예를 들면:

```text
하루 동안 데이터 수집
        ↓
밤에 한 번에 처리
```

즉, 데이터가 들어오는 즉시 처리하는 것이 아니라  
일정 시간이나 일정량을 기준으로 모아서 처리한다.

### 💡 내가 이해한 방식

```text
Batch
= 모아두고 한 번에 처리
```

### ⭐ 기억하기

```text
Batch = 묶어서 처리
```

---

# ⚡ Streaming

Streaming은  
데이터가 들어오는 대로  
**실시간에 가깝게 계속 처리하는 방식**이다.

예를 들면:

```text
데이터 발생
   ↓
바로 처리
   ↓
다음 데이터 발생
   ↓
또 처리
```

실시간 로그나 센서 데이터처럼  
빠르게 처리해야 하는 상황에서 사용할 수 있다.

### 💡 내가 이해한 방식

```text
Streaming
= 들어오는 즉시 계속 처리
```

### ⭐ 기억하기

```text
Streaming = 실시간 처리
```

---

# 🤔 Batch vs Streaming

오늘 다시 구분해서 정리했다.

### Batch

```text
데이터
데이터
데이터
데이터

   ↓ 모음

한 번에 처리
```

### Streaming

```text
데이터 → 처리
데이터 → 처리
데이터 → 처리
데이터 → 처리
```

### ⭐ 시험에서 기억하기

```text
일정량을 모아서 처리
→ Batch

실시간으로 계속 처리
→ Streaming
```

# 🌅 1. 아침 공부

아침에는 AWS의 데이터 이동 / 마이그레이션 서비스들을 중심으로 복습했다.

주요 내용:

```text
AWS DMS(Database Migration Service, 데이터베이스 마이그레이션 서비스)
AWS DataSync(데이터 동기화 서비스)
AWS Snowball Edge(대용량 오프라인 데이터 전송 장비)

```

---

# AWS DMS
## Database Migration Service(데이터베이스 마이그레이션 서비스)

DMS는 Database(데이터베이스)의 실제 데이터를  
다른 Database나 AWS의 관리형 Database로 이전할 때 사용하는 서비스다.

```text
Source DB(원본 데이터베이스)
        ↓
       DMS
        ↓
Target DB(대상 데이터베이스)
```

예:

```text
On-Premises PostgreSQL(온프레미스 PostgreSQL)
        ↓
       DMS
        ↓
Amazon RDS
```

### 핵심

```text
DMS
→ 실제 Database Data(데이터) 이동
```

---

# AWS SCT
## Schema Conversion Tool(스키마 변환 도구)

SCT는 서로 다른 Database Engine(데이터베이스 엔진)으로 이전할 때  
Schema(스키마 / 데이터베이스 구조)를 변환하는 데 사용한다.

```text
기존 DB Schema
      ↓
     SCT
      ↓
대상 DB Engine에 맞는 Schema
```

예:

```text
Oracle
  ↓
 SCT
  ↓
PostgreSQL
```

### 핵심

```text
DMS
→ Data(데이터) 이동

SCT
→ Schema(구조) 변환
```

---

# AWS DataSync
## 데이터 동기화 서비스

DataSync는 Database 자체를 이전하는 서비스가 아니라  
File(파일), NAS(Network Attached Storage, 네트워크 연결 저장소) 등의 데이터를  
네트워크를 통해 AWS Storage(스토리지)로 복사하거나 동기화할 때 사용하는 서비스다.

예:

```text
On-Premises NAS
      ↓
   DataSync
      ↓
Amazon S3
```

또는:

```text
On-Premises File Server(파일 서버)
      ↓
   DataSync
      ↓
EFS / FSx / S3
```

### 핵심

```text
DataSync
→ File / NAS
→ 네트워크 기반 전송 / 동기화
```

---

# DMS vs DataSync

이 둘은 데이터 이동이라는 공통점 때문에 헷갈릴 수 있다.

```text
DMS
→ Database 이동

DataSync
→ File / NAS 이동
```

한 줄로:

```text
DB면 DMS
파일/NAS면 DataSync
```

### 이해 상태

아침에 Migration(마이그레이션) 서비스를 묶어서 보면서  
서비스 이름보다 **무엇을 옮기는지**를 기준으로 구분했다.

```text
DMS
→ DB

DataSync
→ File / NAS
```

이 기준을 다시 잡은 상태였다.

---

# AWS Snowball Edge
## 대용량 오프라인 데이터 전송 장비

Snowball Edge는 네트워크를 통해 데이터를 보내기 어렵거나  
데이터 양이 매우 큰 경우 물리 장비를 이용해 데이터를 이전하는 방식이다.

개념적으로:

```text
대용량 데이터
+
네트워크 전송이 비효율적
        ↓
Snowball Edge
        ↓
물리 장비로 데이터 이동
```

### DataSync와 비교

```text
DataSync
→ Network(네트워크)를 이용한 데이터 전송

Snowball Edge
→ Physical Device(물리 장비)를 이용한 대용량 전송
```

### 핵심

```text
네트워크로 파일 동기화
→ DataSync

네트워크로 보내기 어려울 만큼 대용량
→ Snowball Edge
```

---

# 아침 Migration 서비스 전체 비교

| 서비스 | 한국어 의미 | 핵심 역할 |
| --- | --- | --- |
| DMS | 데이터베이스 마이그레이션 서비스 | DB Data 이동 |
| SCT | 스키마 변환 도구 | DB Schema 변환 |
| DataSync | 데이터 동기화 서비스 | File / NAS 네트워크 전송 |
| Snowball Edge | 대용량 오프라인 전송 장비 | 물리 장비를 통한 대용량 전송 |

한 번에 정리:

```text
Database Data
→ DMS

Database Schema
→ SCT

File / NAS + Network
→ DataSync

Very Large Data + Physical Transfer
→ Snowball Edge
```

# Glue / Athena 연결 복습

아침에는 이전에 공부했던 Glue와 Athena 맥락도 함께 연결해서 봤다.

## AWS Glue
### Serverless ETL(서버리스 ETL)

```text
ETL
= Extract(추출)
+ Transform(변환)
+ Load(적재)
```

Glue는 데이터를 분석에 사용할 수 있도록  
정리하고 변환하는 ETL 서비스다.

## Amazon Athena
### S3 SQL Query Service(S3 SQL 조회 서비스)

Athena는 S3에 저장된 데이터를  
SQL로 직접 조회할 수 있는 Serverless(서버리스) 분석 서비스다.

```text
S3
 ↓
Athena
 ↓
SQL Query(SQL 조회)
```

### 구분

```text
Glue
→ 데이터를 가공 / 변환

Athena
→ S3 데이터를 SQL로 조회
```

# DMS + CDC

## CDC
### Change Data Capture(변경 데이터 캡처)

CDC는 원본 Database에서 발생하는 변경사항을 계속 추적해서  
대상 Database에 반영하는 방식이다.

예:

```text
PostgreSQL
   ↓
DMS + CDC
   ↓
Amazon RDS
```

Migration(마이그레이션) 중에도 서비스가 계속 사용되어  
데이터가 변경된다면:

```text
초기 데이터 이동
+
이후 발생한 변경사항 계속 반영
```

이 필요하다.

이때 DMS + CDC를 사용할 수 있다.

### 핵심

```text
DMS
→ Database Migration

CDC
→ 변경 데이터 계속 추적 / 반영
```

---

# DataSync vs DMS + CDC

저녁 공부에서 이 둘의 차이를 다시 확인했다.

## DataSync

```text
NAS
File Server
File Data
→ AWS Storage로 동기화
```

## DMS + CDC

```text
Database
→ 다른 Database로 Migration
→ 서비스 중 변경 데이터도 계속 반영
```

### 다시 구분

```text
파일/NAS
→ DataSync

DB 이전 + 지속적인 변경 반영
→ DMS + CDC
```

### 이해 상태

이 부분은 다시 비교하면서 개념을 잡았다.

```text
DataSync
→ 파일 기반

DMS + CDC
→ DB 기반 + 변경사항 지속 반영
```

---

# AWS Transfer Family
## 관리형 파일 전송 서비스

Transfer Family는 기존 시스템에서 사용하던  
SFTP / FTP / FTPS 같은 File Transfer Protocol(파일 전송 프로토콜)을 유지하면서  
AWS Storage와 연결할 때 사용할 수 있다.

예:

```text
기존 SFTP Client
      ↓
AWS Transfer Family
      ↓
Amazon S3
```

### 핵심

```text
SFTP / FTP를 유지해서 AWS에 파일 전송
→ Transfer Family
```

---

# DataSync vs Transfer Family

둘 다 파일을 AWS로 옮길 수 있지만 문제의 표현이 다르다.

```text
NAS / File Server를 대량 동기화
→ DataSync

SFTP / FTP 방식 유지
→ Transfer Family
```

### 기억하기

```text
"동기화"
→ DataSync

"SFTP / FTP"
→ Transfer Family
```

---

# AWS Glue DataBrew
## No-Code Data Preparation(노코드 데이터 준비 / 정제)

DataBrew는 코드를 직접 작성하지 않고  
Visual Interface(시각적 인터페이스)를 이용해 데이터를 정리하거나 변환할 수 있다.

예:

```text
중복 제거
값 정리
Column(열) 변환
형식 변경
```

### 핵심

```text
DataBrew
→ No-Code(노코드)
→ Visual(시각적)
→ Data Cleaning / Transformation(데이터 정제 / 변환)
```

---

# AWS Glue
## Serverless ETL(서버리스 ETL)

Glue는 Python / Spark 등을 이용해  
ETL 작업을 수행할 수 있다.

```text
Extract(추출)
→ Transform(변환)
→ Load(적재)
```

### DataBrew와 비교

```text
Glue DataBrew
→ 화면에서 No-Code로 정제

AWS Glue
→ Python / Spark 기반 ETL
```

### 이해 상태

저녁 공부에서:

```text
No-Code Cleaning
→ DataBrew

Code / Spark ETL
→ Glue
```

로 다시 구분했다.

---

# AWS Glue Data Quality
## 데이터 품질 검사

Glue Data Quality는 데이터를 직접 수정하는 도구라기보다  
정해진 Rule(규칙)에 따라 데이터 품질을 검사하는 데 초점이 있다.

예:

```text
order_id는 NULL이면 안 된다
중복 값이 없어야 한다
값이 특정 범위 안에 있어야 한다
```

이런 Rule을 검사한다.

### 핵심

```text
DataBrew
→ 데이터를 정제 / 수정

Glue Data Quality
→ 데이터 품질 규칙 검사
```

---

# DataBrew vs Glue Data Quality

이 둘도 비슷해 보여서 구분이 중요하다.

```text
DataBrew
→ Data를 직접 Clean / Transform
→ 데이터 정제 / 변환

Glue Data Quality
→ Rule을 이용해 Data 상태 검사
→ 데이터 품질 확인
```

한 줄로:

```text
고친다
→ DataBrew

검사한다
→ Data Quality
```

---

# AWS Lake Formation
## 데이터 레이크 권한 관리

Lake Formation은 Data Lake(데이터 레이크)의  
데이터 접근 권한을 중앙에서 관리하는 데 사용한다.

특히 Fine-Grained Permission(세분화된 권한)을 관리할 수 있다.

예:

```text
어떤 사용자
→ 어떤 Table(테이블)
→ 어떤 Column(열)
→ 어떤 데이터에 접근 가능?
```

같은 권한을 관리한다.

### 핵심

```text
Lake Formation
→ Data Lake 중앙 권한 관리
→ Fine-Grained Access Control(세분화된 접근 제어)
```

---

# AWS Glue Crawler
## Schema 자동 탐색

Glue Crawler는 S3 등의 데이터 소스를 확인해서  
Schema(스키마 / 데이터 구조)를 자동으로 찾아낸다.

예:

```text
S3 File
  ↓
Glue Crawler
  ↓
Schema 탐색
  ↓
Glue Data Catalog에 Table 등록
```

### 핵심

```text
Crawler
→ Schema 발견
→ Data Catalog 등록
```

---

# Glue Crawler vs Lake Formation

```text
Glue Crawler
→ 데이터 구조를 찾음

Lake Formation
→ 누가 데이터에 접근할 수 있는지 관리
```

즉:

```text
Schema(구조)
→ Crawler

Permission(권한)
→ Lake Formation
```

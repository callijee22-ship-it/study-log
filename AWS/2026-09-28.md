# 🪣 Amazon S3 다시 보기

S3는 Object Storage 서비스이다.

데이터를 Object 형태로 저장하고  
Bucket을 이용해서 관리한다.

```text
S3
│
├── Bucket
│     ├── Object
│     ├── Object
│     └── Object
│
└── Storage Class
      ├── Standard
      ├── Standard-IA
      ├── Intelligent-Tiering
      └── Glacier 계열
```

### ⭐ 기본 기억

```text
S3 = Object Storage
```

---

# 📦 S3 Standard

자주 사용하는 데이터를 위한 기본 Storage Class이다.

데이터에 자주 접근해야 하고  
빠르게 사용할 필요가 있을 때 적합하다.

### 내가 이해한 방식

```text
자주 사용하는 데이터
        ↓
   S3 Standard
```

### ⭐ 기억하기

```text
Standard = 자주 접근
```

---

# 📦 S3 Standard-IA

IA는 **Infrequent Access**의 약자이다.

자주 사용하지는 않지만  
필요할 때는 바로 접근해야 하는 데이터에 사용할 수 있다.

### 내가 이해한 방식

```text
자주 사용하지 않음
        +
필요하면 바로 꺼내야 함
        ↓
   Standard-IA
```

### ⭐ 기억하기

```text
Standard-IA
= 자주 안 쓰지만 빠른 접근 필요
```

---

# 🔄 S3 Intelligent-Tiering

데이터의 접근 패턴을 미리 알기 어려운 경우 사용할 수 있다.

AWS가 데이터의 접근 패턴을 보고  
적절한 Access Tier로 이동시켜 관리한다.

### 예시

```text
어떤 파일은 자주 사용
어떤 파일은 거의 사용 안 함
어떤 파일은 언제 쓸지 모름

        ↓

접근 패턴 예측 어려움

        ↓

Intelligent-Tiering
```

### 💡 내가 이해한 방식

```text
얼마나 자주 사용할지 모르겠다?
→ Intelligent-Tiering
```

### ⭐ 기억하기

```text
Intelligent-Tiering
= 접근 패턴을 모를 때
```

---

# 🧊 S3 Glacier

Glacier 계열은  
자주 사용하지 않는 데이터를 장기간 보관할 때 사용한다.

오늘은 특히

- Glacier Flexible Retrieval
- Glacier Deep Archive

를 구분해서 공부했다.

---

# 🧊 Glacier Flexible Retrieval

오랫동안 보관할 데이터이지만  
가끔 다시 꺼낼 가능성이 있는 경우 사용할 수 있다.

즉,

```text
장기 보관
   +
가끔 복원 가능성 있음
```

이라고 생각했다.

### ⭐ 기억하기

```text
Flexible Retrieval
= 장기 보관 + 필요하면 복원
```

---

# 🧊 Glacier Deep Archive

매우 오랫동안 보관하고  
거의 접근하지 않는 데이터를 위한 Storage Class이다.

예를 들면:

```text
장기 기록
법적 보관 자료
오래된 백업
거의 사용하지 않는 데이터
```

처럼 즉시 사용할 필요가 없는 경우를 생각할 수 있다.

### 내가 이해한 방식

```text
거의 안 봄
   +
아주 오래 보관
   +
비용 최소화
        ↓
Deep Archive
```

### ⭐ 기억하기

```text
Deep Archive
= 아주 오래 + 거의 안 씀
```

---

# 🤔 Flexible Retrieval vs Deep Archive

이름이 비슷해서 문제에서 헷갈리기 쉬웠다.

## Glacier Flexible Retrieval

```text
장기간 보관
+
가끔 꺼낼 가능성 있음
```

## Glacier Deep Archive

```text
아주 장기간 보관
+
거의 꺼내지 않음
+
저장 비용을 최대한 줄임
```

### ⭐ 구분하기

```text
가끔 복원해야 한다
→ Flexible Retrieval

거의 사용할 일이 없다
→ Deep Archive
```

---

# 🔄 S3 Lifecycle

Lifecycle은 데이터의 상태나 시간이 지나면서  
Storage Class를 자동으로 변경할 수 있도록 만드는 규칙이다.

예를 들면:

```text
처음 생성된 파일
      ↓
S3 Standard
      ↓
30일 후
      ↓
Standard-IA
      ↓
오래 지나면
      ↓
Glacier
```

사람이 매번 직접 파일을 옮기지 않아도  
미리 규칙을 만들어두면 자동으로 이동할 수 있다.

### 💡 내가 이해한 방식

```text
시간이 지나면
   ↓
더 저렴한 곳으로
   ↓
자동 이동
```

### ⭐ 기억하기

```text
Lifecycle
= Storage Class 자동 이동
```

---

# 🧠 Storage Class 선택 기준

오늘 문제를 풀면서  
Storage Class를 이름으로 외우기보다  
질문의 조건을 먼저 보려고 했다.

## 1️⃣ 얼마나 자주 사용하는가?

```text
자주 사용
→ Standard

자주 사용하지 않음
→ Standard-IA / Glacier 계열 고려
```

---

## 2️⃣ 접근 패턴을 알고 있는가?

```text
접근 패턴을 예측하기 어려움
→ Intelligent-Tiering
```

---

## 3️⃣ 바로 꺼내야 하는가?

```text
자주 안 쓰지만
필요하면 바로 접근해야 함
→ Standard-IA
```

---

## 4️⃣ 장기간 보관하는가?

```text
오랫동안 보관
→ Glacier 계열
```

---

## 5️⃣ 거의 사용하지 않는가?

```text
아주 오래 보관
+
거의 접근하지 않음
→ Deep Archive
```

---

# 🧩 문제에서 이렇게 생각하기

S3 문제가 나오면  
바로 선택지를 고르지 않고 다음 순서로 생각하기로 했다.

```text
1. 자주 사용하는 데이터인가?

        ↓

2. 접근 패턴을 예측할 수 있는가?

        ↓

3. 데이터를 바로 꺼내야 하는가?

        ↓

4. 얼마나 오래 보관해야 하는가?

        ↓

5. 비용을 얼마나 줄여야 하는가?
```

이 조건을 먼저 확인한 뒤  
Storage Class를 선택하는 방식으로 문제를 풀었다.

# 🤔 오늘 헷갈렸던 것

## 1. Standard-IA와 Intelligent-Tiering

둘 다 자주 사용하지 않는 데이터 문제에서  
나올 수 있어서 처음에는 헷갈렸다.

다시 정리하면:

```text
Standard-IA
= 자주 안 쓰는 것을 알고 있음
= 필요하면 빠르게 접근

Intelligent-Tiering
= 얼마나 자주 사용할지 모름
```

---

## 2. Lifecycle과 Intelligent-Tiering

둘 다 데이터가 다른 Tier로 이동한다는 점 때문에 헷갈렸다.

```text
Lifecycle
= 내가 규칙을 설정

Intelligent-Tiering
= 접근 패턴에 따라 관리
```

### ⭐ 기억하기

```text
규칙대로 이동
→ Lifecycle

패턴을 모르겠음
→ Intelligent-Tiering
```

---

## 3. Glacier Flexible Retrieval과 Deep Archive

둘 다 장기 보관용이라 헷갈렸다.

```text
Flexible Retrieval
= 장기 보관하지만 복원 가능성 있음

Deep Archive
= 거의 사용하지 않는 초장기 보관
```

비슷한 문제가 나오면 계속 반복해서 답을 골라봤다.

```text

```

조금씩 구분되기 시작했다.

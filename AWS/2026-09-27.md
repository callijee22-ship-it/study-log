# ☁️ AWS Study Log — 2026-09-27

## 📌 오늘 공부한 것

오늘은 AWS의 데이터 처리 서비스들을 다시 비교하면서 공부했다.

특히 이름이 비슷하게 느껴졌던

- AWS Lambda
- AWS Glue
- Amazon EMR

이 세 가지가 각각 어떤 상황에서 사용되는지 구분하는 데 집중했다.

서비스 이름만 외우기보다  
**“이 서비스가 실제로 무슨 일을 하는가?”**를 기준으로 정리했다.

---

# ⚡ AWS Lambda

Lambda는 서버를 직접 관리하지 않고  
코드를 실행할 수 있는 **Serverless Compute 서비스**이다.

특정 이벤트가 발생했을 때  
자동으로 코드를 실행하도록 만들 수 있다.

예를 들면:

```text
파일 업로드
    ↓
이벤트 발생
    ↓
Lambda 실행
    ↓
코드 처리
```

### 💡 내가 이해한 방식

```text
무언가 발생하면
      ↓
Lambda가 반응해서
      ↓
코드를 실행한다
```

### ⭐ 기억하기

```text
Lambda = 이벤트 기반 코드 실행
```

---

# 🔔 Event-driven

Lambda를 공부하면서  
Event-driven이라는 개념도 같이 정리했다.

Event-driven은  
**특정 사건(Event)이 발생하면 그에 맞는 작업이 실행되는 방식**이다.

예를 들면:

```text
S3에 파일 업로드
       ↓
Event 발생
       ↓
Lambda 실행
```

또는:

```text
메시지 도착
    ↓
Event
    ↓
처리 작업 시작
```

### ⭐ 기억하기

```text
Event-driven
= 사건이 발생하면 작업 실행
```

---

# 🧹 AWS Glue

Glue는 데이터를 분석하기 전에  
정리하고 변환하는 데 사용할 수 있는 서비스이다.

앞에서 공부했던 ETL과 연결해서 다시 이해했다.

```text
Extract
   ↓
Transform
   ↓
Load
```

### 내가 이해한 방식

```text
원본 데이터
     ↓
Glue
     ↓
정리된 데이터
```

### ⭐ 기억하기

```text
Glue = 데이터 ETL / 변환
```

---

# 🕷️ Glue Crawler

Glue Crawler도 다시 복습했다.

Crawler는 데이터 소스를 살펴보고  
데이터의 구조를 자동으로 파악한다.

```text
S3 데이터
    ↓
Crawler
    ↓
Schema 확인
    ↓
Data Catalog
```

### ⭐ 기억하기

```text
Crawler = Schema 자동 탐색
```

---

# 📚 Glue Data Catalog

Data Catalog는  
데이터 자체를 저장하는 곳이라기보다

**데이터가 어떤 구조로 되어 있는지에 대한 정보**를 관리한다.

예:

```text
Column 이름
데이터 Type
Table 정보
Schema
```

### ⭐ 기억하기

```text
Data Catalog
= 데이터에 대한 정보
= Metadata 관리
```

---

# 🐘 Amazon EMR

EMR은 대규모 데이터를 처리하기 위한 서비스이다.

특히 Apache Spark나 Hadoop 같은  
빅데이터 처리 기술을 AWS에서 사용할 수 있도록 도와준다.

처음에는 Glue와 EMR이 둘 다 데이터를 처리해서  
차이가 헷갈렸다.

### 내가 이해한 방식

```text
대규모 데이터
      ↓
Spark / Hadoop 필요
      ↓
EMR
```

### ⭐ 기억하기

```text
EMR = 대규모 빅데이터 처리
```

---

# 🤔 Glue vs EMR

오늘 중요하게 구분한 부분이다.

둘 다 데이터를 처리할 수 있지만  
문제에서 요구하는 상황이 다르다.

## AWS Glue

```text
데이터
  ↓
ETL
  ↓
정리 / 변환
```

- Serverless
- ETL 작업
- 데이터 변환
- Glue Crawler
- Data Catalog

### 기억하기

```text
ETL 중심
→ Glue
```

---

## Amazon EMR

```text
대규모 데이터
      ↓
Spark / Hadoop
      ↓
분산 처리
```

- 빅데이터 처리
- Spark
- Hadoop
- 대규모 분산 처리

### 기억하기

```text
Spark / Hadoop
→ EMR
```

---

# ⚡ Lambda vs Glue

Lambda와 Glue도  
둘 다 Serverless라는 특징 때문에 처음에는 헷갈릴 수 있다.

### Lambda

```text
Event 발생
    ↓
짧은 코드 실행
```

### Glue

```text
데이터
  ↓
ETL 작업
  ↓
변환
```

### ⭐ 구분하기

```text
이벤트가 발생해서 코드 실행
→ Lambda

데이터 ETL / 변환
→ Glue
```

---

# 🧠 Lambda vs Glue vs EMR

오늘 공부한 세 서비스를 한 번에 비교했다.

```text

└── 이벤트 발생

    코드 실행
```

```text

Spark / Hadoop
→ EMR
```

# 🖥️ Serverless

오늘 공부한 서비스 중  
Lambda와 Glue에서 Serverless라는 말이 계속 등장했다.

Serverless는 서버가 실제로 없다는 뜻이 아니라

**사용자가 서버를 직접 구성하고 관리하는 부담을 줄여주는 방식**으로 이해했다.

### 내가 이해한 방식

```text
서버를 직접 만들고 관리
        X

필요한 기능에 집중
        O
```

### ⭐ 기억하기

```text
Serverless
= 서버 관리 부담을 줄이고 기능에 집중
```

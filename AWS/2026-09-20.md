## 🪣 Amazon S3

S3의 기본 구조를 공부했다.

- Bucket
- Object
- Key

S3는 데이터를 저장하는 서비스이고,  
파일을 저장할 때 **Bucket 안에 Object가 들어가는 구조**로 이해했다.

### 💡 내가 이해한 방식

```text
Bucket = 데이터를 담는 큰 공간
Object = 실제 저장되는 파일과 데이터
Key = Object를 구분하는 이름 또는 경로
```

---

## 📦 S3 Storage Class

데이터를 얼마나 자주 사용하는지에 따라  
저장 방식을 다르게 선택할 수 있다는 것을 배웠다.

공부한 저장 클래스:

- S3 Standard
- S3 Standard-IA
- S3 Intelligent-Tiering
- S3 Glacier 계열

### 💡 기억하기

접근 패턴을 예측하기 어렵다면:

> S3 Intelligent-Tiering

오랫동안 보관하면서 비용을 줄이고 싶다면:

> Lifecycle을 이용해 Glacier 계열로 이동

---

## 🔄 Lifecycle

파일을 일정 기간 보관한 뒤  
더 저렴한 저장 방식으로 자동 이동할 수 있다는 것을 배웠다.

예를 들면:

```text
S3 Standard
      ↓
일정 기간 경과
      ↓
Glacier 계열
```

즉, 오래된 데이터를 사람이 직접 옮기지 않아도  
규칙을 설정해두면 자동으로 저장 클래스를 변경할 수 있다.

---

## 🕒 Versioning

같은 파일이 변경되어도  
이전 버전을 보관할 수 있는 기능이라는 것을 공부했다.

파일을 실수로 수정하거나 삭제했을 때  
이전 버전을 이용해 복구할 수 있다는 점이 중요했다.

### ⭐ 기억하기

```text
Versioning = 파일의 이전 버전을 보관
```

---

## 🔗 AWS 데이터 처리 흐름

처음으로 AWS의 데이터 처리 흐름도 같이 공부했다.

```text
S3
 ↓
Glue
 ↓
Athena
```

아직 각 서비스의 모든 기능을 외우기보다는  
우선 전체적인 역할을 구분하는 데 집중했다.

### 내가 이해한 역할

```text
S3     = 데이터 저장
Glue   = 데이터를 정리하고 사용할 수 있도록 준비
Athena = S3의 데이터를 SQL로 조회
```

---

## ❌ 문제풀이에서 기억할 것

### Q. 데이터를 오랫동안 보관하면서 저장 비용을 줄이고 싶다면?

Lifecycle을 이용해서  
일정 시간이 지난 데이터를 Glacier 계열로 이동할 수 있다.

```text
Standard
   ↓
Lifecycle
   ↓
Glacier
```

---

### Q. 데이터 접근 패턴을 예측하기 어렵다면?

> S3 Intelligent-Tiering

접근 빈도가 일정하지 않은 데이터를  
자동으로 적절한 계층에서 관리할 수 있다.

## 🤔 오늘 헷갈렸던 것

AWS 서비스 이름이 한꺼번에 많이 나오니까  
처음에는 무엇이 저장 서비스이고  
무엇이 데이터를 처리하거나 분석하는 서비스인지 구분하기 어려웠다.

그래서 서비스 이름을 무작정 외우기보다  
**각 서비스의 역할을 먼저 연결해서 기억하기로 했다.**

```text
저장 → S3

정리 → Glue

조회 → Athena
```

---

## 💡 다시 이해한 내용

S3 안에서도 모든 데이터를 똑같은 방식으로 저장하는 것이 아니다.

데이터를 얼마나 자주 사용하는지,  
얼마나 오래 보관해야 하는지에 따라서  
적절한 Storage Class를 선택할 수 있다.

그리고 Lifecycle을 이용하면  
시간이 지난 데이터를 자동으로 더 저렴한 저장 클래스로 이동할 수 있다.

---

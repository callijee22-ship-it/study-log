## ☁️ Cloud 기본 개념

AWS는 인터넷을 통해 서버, 저장공간, 데이터베이스 같은  
IT 자원을 필요한 만큼 사용할 수 있는 Cloud 서비스이다.

직접 서버 장비를 준비하지 않고도  
필요한 자원을 사용할 수 있다는 점을 먼저 이해했다.

---

## 🌏 Region / Availability Zone

AWS의 기본적인 인프라 구조를 공부했다.

```text
Region
  ↓
Availability Zone (AZ)
  ↓
Data Center
```

### Region

AWS의 서비스가 운영되는 **지리적인 지역**이다.

예:

```text
서울 Region
도쿄 Region
버지니아 Region
```

### Availability Zone

하나의 Region 안에는  
여러 개의 Availability Zone이 존재한다.

Availability Zone은 서로 분리되어 있어서  
한 곳에 문제가 생겨도 다른 AZ를 활용할 수 있다.

### ⭐ 기억하기

```text
Region = 큰 지역

AZ = Region 안의 독립된 영역
```

---

## 📈 Scalability

Scalability는  
사용량이 증가했을 때 시스템의 처리 능력을 확장할 수 있는 능력이다.

### 내가 이해한 방식

```text
사용자 증가
   ↓
필요한 서버 자원 증가
   ↓
시스템 확장
```

### 발음

```text
Scalability
→ 스케일러빌리티
```

---

## 🏢 Availability Zone 발음

공부하면서 영어 발음도 같이 확인했다.

```text
Availability Zone
→ 어베일러빌리티 존
```

AWS 문제를 읽을 때 용어 자체가 낯설지 않도록  
영어 표현과 뜻을 같이 익히기로 했다.

---

## 💻 Amazon EC2

EC2는 AWS에서 사용하는 **가상 서버**이다.

직접 물리 서버를 준비하지 않고도  
필요한 컴퓨팅 자원을 사용할 수 있다.

### ⭐ 기억하기

```text
EC2 = 가상 서버
```

---

## 🔐 IAM

IAM은 AWS의 **사용자와 권한을 관리하는 서비스**이다.

누가 어떤 AWS 서비스에 접근할 수 있는지  
권한을 설정할 때 사용한다.

### 내가 이해한 방식

```text
사용자
  ↓
IAM
  ↓
접근 권한 결정
```

### ⭐ 기억하기

```text
IAM = 권한 관리
```

---

## ⚡ AWS Lambda

Lambda는 서버를 직접 관리하지 않고  
코드를 실행할 수 있는 Serverless 서비스이다.

특정 이벤트가 발생했을 때  
코드가 자동으로 실행되도록 만들 수 있다.

### 내가 이해한 방식

```text
이벤트 발생
    ↓
Lambda 실행
    ↓
코드 동작
```

### ⭐ 기억하기

```text
Lambda = 이벤트 기반 + Serverless 실행
```

# 📦 어제 공부한 S3 복습

## S3 기본 구조

```text
Bucket
  └── Object
        └── Key
```

- Bucket = 데이터를 담는 공간
- Object = 실제 저장되는 데이터
- Key = Object의 이름 또는 경로

### ⭐ 다시 기억하기

```text
S3 = 파일 / Object 저장
```

---

## 🔄 Lifecycle

데이터가 오래되면  
자동으로 다른 Storage Class로 이동시키거나 삭제하도록 설정할 수 있다.

```text
S3 Standard
      ↓
Lifecycle
      ↓
Glacier
```

### ⭐ 기억하기

```text
Lifecycle = 시간이 지나면 자동 이동 / 삭제
```

---

## 🕒 Versioning

파일의 이전 버전을 보관할 수 있는 기능이다.

실수로 파일을 수정하거나 삭제했을 때  
이전 버전으로 복구할 수 있다.

```text
Versioning = 이전 버전 복구
```

---

## 🔐 KMS

KMS는 암호화에 사용하는 **Key를 관리하는 서비스**이다.

S3 데이터 암호화 문제를 공부하면서 같이 복습했다.

### ⭐ 기억하기

```text
KMS = 암호화 Key 관리
```

# 🔗 AWS 데이터 처리 흐름

오늘은 데이터가 AWS에서  
어떻게 저장되고 분석되는지도 공부했다.

```text
데이터
  ↓
S3
  ↓
Glue
  ↓
Athena / Redshift
```

---

## 🪣 Amazon S3

데이터를 저장하는 공간이다.

데이터 분석 과정에서는  
원본 데이터를 보관하는 Data Lake 역할로도 사용할 수 있다.

### ⭐ 기억하기

```text
S3 = 저장
```

---

## 🧹 AWS Glue

Glue는 데이터를 정리하고 변환하는 데 사용하는 서비스이다.

ETL 과정에서 사용할 수 있다.

```text
Extract
Transform
Load
```

### 내가 이해한 방식

```text
데이터 가져오기
      ↓
필요한 형태로 정리
      ↓
사용할 곳으로 전달
```

### ⭐ 기억하기

```text
Glue = 데이터 정리 / 변환
```

---

## 🕷️ Glue Crawler

Glue Crawler는 데이터를 살펴보고  
Schema를 자동으로 찾아주는 기능이다.

찾은 정보는 Data Catalog에 등록할 수 있다.

### 내가 이해한 방식

```text
S3 데이터
   ↓
Glue Crawler
   ↓
데이터 구조 확인
   ↓
Data Catalog
```

### ⭐ 기억하기

```text
Crawler = Schema 자동 탐색
```

---

## 📚 Data Catalog

데이터가 어떤 구조인지에 대한 정보를 저장한다.

실제 데이터 자체를 저장하는 것이 아니라  
**데이터에 대한 정보**를 관리한다고 이해했다.

```text
Data Catalog
= 데이터 구조 정보
```

---

## 🔍 Amazon Athena

Athena는 S3에 저장된 데이터를  
SQL을 이용해 조회할 수 있는 서비스이다.

별도의 서버를 직접 준비하지 않아도 된다.

### 내가 이해한 방식

```text
S3에 데이터 저장
      ↓
Athena
      ↓
SQL로 조회
```

### ⭐ 기억하기

```text
Athena = S3 + SQL + Serverless
```

---

## 🏢 Amazon Redshift

Redshift는 대규모 데이터를 분석하기 위한  
Data Warehouse 서비스이다.

Athena와 비슷하게 데이터 분석에 사용되기 때문에  
두 서비스를 구분하는 것이 처음에는 헷갈렸다.

### ⭐ 기억하기

```text
Redshift = Data Warehouse
```

---

# 🤔 Athena vs Redshift

오늘 특히 헷갈렸던 부분이다.

둘 다 데이터를 분석할 때 사용할 수 있지만  
사용 방식이 다르다.

### Athena

```text
S3에 있는 데이터
      ↓
필요할 때 SQL로 조회
```

- Serverless
- S3 데이터를 직접 조회
- 필요한 순간에 Query 실행

### Redshift

```text
대규모 분석 데이터
      ↓
Data Warehouse
      ↓
반복적인 분석
```

- Data Warehouse
- 대규모 데이터 분석에 사용

### ⭐ 시험에서 기억하기

```text
S3 데이터를 바로 SQL로 조회
→ Athena

Data Warehouse
→ Redshift
```

## 🤔 오늘 헷갈렸던 것

### 1. Athena와 Redshift

둘 다 분석 서비스라 처음에는 비슷하게 느껴졌다.

그래서 이렇게 구분해서 기억하기로 했다.

```text
Athena
= S3 데이터를 SQL로 바로 보기

Redshift
= Data Warehouse에서 대규모 분석
```

### 2. Glue와 Glue Crawler

처음에는 같은 기능처럼 느껴졌다.

```text
Glue
= 데이터 정리 / 변환

Glue Crawler
= 데이터 구조를 찾아줌
```

### 3. Region과 AZ

```text
Region
  ↓
여러 개의 AZ
```

큰 지역 안에 여러 Availability Zone이 있다고 기억한다.

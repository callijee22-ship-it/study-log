# ☁️ 2026-10-02 AWS Study

## 📌 오늘의 기록

오늘은 이동 중과 이후 복습 시간에 AWS 문제를 이어서 풀었다.

오늘은 비슷한 서비스들이 계속 섞여 보여서 서비스 이름만 외우기보다

~~~text
무엇을 기록하는지
무엇을 실제로 처리하는지
무엇을 분석하는지
무엇을 자동화하는지
~~~

를 기준으로 구분했다.

영어 용어는 가능한 한 한국어 뜻을 같이 적는다.

# 1. S3 Event Notifications(이벤트 알림) vs EventBridge(이벤트브리지)

처음 다시 본 문제는 다음과 같은 상황이었다.

~~~text
S3에 파일 업로드
→ 별도 복잡한 조건 없음
→ 바로 Lambda 실행
~~~

## S3 Event Notifications(이벤트 알림)

S3에서 특정 이벤트가 발생했을 때 다른 서비스로 바로 알림을 보낼 수 있다.

예:

~~~text
Object Created(객체 생성)
→ Lambda

Object Deleted(객체 삭제)
→ SQS / SNS
~~~

핵심:

~~~text
S3 이벤트 발생
→ 바로 반응
~~~

## Amazon EventBridge(이벤트브리지)

EventBridge는 Event(이벤트)를 받아 Rule(규칙)이나 Event Pattern(이벤트 패턴)에 따라 어디로 보낼지 결정한다.

~~~text
Event
 ↓
EventBridge
 ↓
Rule 확인
 ↓
Target 실행
~~~

구분:

~~~text
Event Notifications
→ 단순하고 직접적인 S3 이벤트 알림

EventBridge
→ 조건 / 규칙 기반 이벤트 라우팅
~~~

### 이해 상태

~~~text
단순 S3 이벤트 즉시 반응
→ Event Notifications

조건 / 규칙 기반
→ EventBridge
~~~

로 다시 구분했다.

# 2. S3 Inventory(인벤토리) / Batch Operations(배치 작업) / Storage Lens(스토리지 렌즈)

오늘 가장 많이 반복해서 구분한 부분 중 하나였다.

## S3 Inventory(인벤토리)

S3 객체들의 상태와 속성을 정기적인 목록 형태로 확인할 수 있다.

예:

~~~text
Object Name(객체 이름)
Size(크기)
Storage Class(스토리지 클래스)
Encryption Status(암호화 상태)
~~~

핵심:

~~~text
Inventory
→ 객체 목록 / 상태 보고서
→ 무엇이 있는지 확인
~~~

## S3 Batch Operations(배치 작업)

많은 S3 객체에 실제 작업을 한꺼번에 수행할 때 사용한다.

예:

~~~text
대량 Tag(태그) 변경
대량 Copy(복사)
대량 Restore(복원)
~~~

핵심:

~~~text
Batch Operations
→ 여러 객체에 실제 작업 실행
~~~

## S3 Storage Lens(스토리지 렌즈)

여러 Bucket(버킷)의 사용 현황을 Dashboard(대시보드) 형태로 분석한다.

예:

~~~text
저장 용량
Object 수
사용 패턴
비용 최적화
~~~

핵심:

~~~text
Storage Lens
→ 여러 Bucket 사용 상태 분석
~~~

## 세 서비스 구분

~~~text
Inventory
→ 목록

Batch Operations
→ 실제 작업

Storage Lens
→ 분석 / 대시보드
~~~

기억:

~~~text
무엇이 있나?
→ Inventory

많은 객체에 작업하고 싶다
→ Batch Operations

전체 사용량과 패턴을 보고 싶다
→ Storage Lens
~~~

### 이해 상태

반복 문제에서:

~~~text
Q6 → Batch Operations
Q7 → Storage Lens
Q8 → Inventory
Q9 → Storage Lens
~~~

를 맞히면서 세 서비스 구분이 처음보다 확실해졌다.

# 3. Amazon Macie(메이시)

Macie는 S3 등에 저장된 데이터에서 PII(Personally Identifiable Information, 개인식별정보) 같은 민감정보를 탐지하는 서비스다.

예:

~~~text
주민번호
이름
이메일
민감한 개인정보
~~~

핵심:

~~~text
Macie
→ Sensitive Data Detection(민감정보 탐지)
~~~

---

# 4. Amazon OpenSearch Service(오픈서치 서비스)

OpenSearch는 Log(로그)나 Document(문서)처럼 검색이 필요한 데이터를 빠르게 검색하고 분석할 때 사용한다.

~~~text
Log Search(로그 검색)
Document Search(문서 검색)
검색 / 분석
~~~

핵심:

~~~text
OpenSearch
→ 검색
→ 로그 분석
~~~

---

# 5. Amazon QuickSight(퀵사이트)

QuickSight는 AWS의 BI(Business Intelligence, 비즈니스 인텔리전스) 서비스다.

데이터를 Graph(그래프)나 Dashboard(대시보드)로 시각화할 때 사용한다.

~~~text
QuickSight
→ Visualization(시각화)
→ BI Dashboard
~~~

## Macie vs OpenSearch vs QuickSight

~~~text
Macie
→ 민감정보 탐지

OpenSearch
→ 로그 / 문서 검색

QuickSight
→ 그래프 / BI Dashboard
~~~

---

# 6. Amazon Managed Service for Apache Flink(플링크)

Flink는 Streaming Data(스트리밍 데이터)를 실시간으로 처리하고 집계할 때 사용한다.

예:

~~~text
실시간 클릭 데이터
실시간 로그
실시간 센서 데이터
~~~

핵심:

~~~text
Flink
→ Real-Time Stream Processing
→ 실시간 스트림 처리
~~~

---

# 7. Amazon MWAA

MWAA는 Managed Workflows for Apache Airflow의 약자다.

Apache Airflow(에어플로)를 AWS에서 관리형으로 사용할 수 있게 해주는 서비스다.

여러 작업의:

~~~text
Schedule(일정)
Order(순서)
Dependency(의존성)
~~~

를 관리한다.

핵심:

~~~text
MWAA
→ Workflow(워크플로)
→ 일정 / 순서 / 의존성 관리
~~~

## Flink vs MWAA

~~~text
Flink
→ 실시간 데이터 자체를 처리

MWAA
→ 여러 작업의 일정과 순서를 관리
~~~

# 8. S3 Versioning(버저닝)

Versioning을 활성화하면 S3 객체가 덮어써지거나 삭제되어도 이전 버전을 보관할 수 있다.

예:

~~~text
report.csv v1
report.csv v2
report.csv v3
~~~

핵심:

~~~text
Versioning
→ 이전 버전 보관
→ 덮어쓰기 / 삭제 후 복구 가능
~~~

### 이해 상태

처음 Versioning 문제에서는:

~~~text
3?
~~~

처럼 잘못 골랐다.

하지만 이후 Q17, Q22 등에서는 Versioning을 다시 맞히면서 개념이 회수됐다.

~~~text
처음
→ 혼동

이후
→ 이전 버전 보관 / 복구 기능으로 다시 정리
~~~

# 9. AWS CloudTrail(클라우드트레일)

CloudTrail은 AWS에서 누가, 언제, 어떤 API 작업을 했는지 기록한다.

예:

~~~text
PutObject
DeleteObject
CreateBucket
권한 변경
~~~

핵심:

~~~text
CloudTrail
→ API Activity Log(API 작업 기록)
→ 누가 무엇을 했는지
~~~

기억:

> 행동 기록

---

# 10. AWS Config(컨피그)

AWS Config는 AWS Resource(리소스)의 Configuration(구성 / 설정) 상태와 변경 이력을 추적한다.

예:

~~~text
Security Group 설정 변경
S3 Bucket 설정 변경
Resource Configuration History
~~~

핵심:

~~~text
Config
→ 리소스 설정 상태
→ 구성 변경 이력
~~~

## CloudTrail vs Config

~~~text
CloudTrail
→ 누가 어떤 API 행동을 했는지

Config
→ Resource 설정이 어떻게 바뀌었는지
~~~

한 줄로:

~~~text
행동 기록
→ CloudTrail

설정 기록
→ Config
~~~

---

# 11. AWS Secrets Manager(시크릿 매니저)

Secrets Manager는 다음과 같은 Secret(비밀정보)을 코드 밖에서 안전하게 저장하고 관리할 때 사용한다.

~~~text
DB Password(데이터베이스 비밀번호)
API Key(API 키)
Secret(비밀정보)
~~~

핵심:

~~~text
Secrets Manager
→ Secret 저장 / 관리
~~~

---

# 12. Parameter Store(파라미터 스토어)

Parameter Store는 Application Configuration(애플리케이션 설정값) 등을 저장할 수 있다.

오늘 복습에서는 우선 다음처럼 구분했다.

~~~text
Secrets Manager
→ 비밀번호 / API Key 같은 Secret

Parameter Store
→ 일반 설정값
~~~

---

# 13. Amazon CloudWatch(클라우드워치)

CloudWatch는 AWS Resource와 Application의 Metric(지표), Log(로그) 등을 모니터링하고 Alarm(알람)을 만들 수 있다.

~~~text
CPU 사용률
Log
Metric
Alarm
~~~

핵심:

~~~text
CloudWatch
→ Monitoring(모니터링)
→ Metric / Log / Alarm
~~~

---

# 14. Amazon SNS

SNS는 Simple Notification Service(단순 알림 서비스)의 약자다.

메시지를 여러 Subscriber(구독자)에게 전달한다.

~~~text
Message
 ↓
SNS Topic
 ↓
Subscriber
~~~

예:

~~~text
Email
SMS
SQS
Lambda
~~~

핵심:

~~~text
SNS
→ Notification(알림)
→ Pub/Sub
~~~

---

# 15. AWS Security Hub(시큐리티 허브)

Security Hub는 여러 AWS 보안 서비스의 보안 상태와 Finding(탐지 결과)을 한 곳에서 모아본다.

~~~text
Security Hub
→ 보안 상태 통합
→ Security Finding 통합
~~~

# 16. IAM

IAM은 Identity and Access Management(자격 증명 및 접근 관리)의 약자다.

AWS에서:

~~~text
누가
어떤 Resource에
무엇을 할 수 있는지
~~~

권한을 관리한다.

## IAM Role(역할)

IAM Role은 특정 사용자 계정 자체가 아니라 AWS Service나 사용자 등이 임시로 맡아서 사용할 수 있는 권한이다.

예:

~~~text
EC2가 S3에 접근해야 함
→ IAM Role 부여
~~~

핵심:

~~~text
IAM
→ 권한 관리

IAM Role
→ 임시로 맡는 권한 역할
~~~

# 📊 오늘의 이해 상태

| 개념 | 상태 |
| --- | --- |

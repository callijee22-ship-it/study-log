# 🌳 2026-08-25 Git Study

> 국비 교육 개강 전 Git 예습 기록

## 📌 오늘의 기록

오늘은 처음으로

> **"Git이 도대체 뭐야?"**

에서 시작했다. 😂

처음에는 Git과 GitHub도 헷갈렸고,  
`add`, `commit`, `push`, `pull` 같은 명령어도 전부 외계어처럼 보였다.

직접 저장소를 이동하고, 상태를 확인하고,  
merge 기록까지 보면서 Git의 기본 흐름을 조금씩 이해했다.

---

# 1. Git이란?

Git은 쉽게 말하면:

> **코드의 변경 이력을 기록하고 관리하는 도구**

라고 이해했다.

게임으로 생각하면:

```text
코드 작성
   ↓
💾 세이브
   ↓
코드 수정
   ↓
💾 또 세이브
```

처럼 변경된 상태를 계속 기록할 수 있다.

---

# 2. Git과 GitHub는 다르다

처음에는 Git과 GitHub가 같은 것처럼 느껴졌다.

하지만 역할이 달랐다.

```text
Git
→ 내 컴퓨터에서 변경 이력을 관리

GitHub
→ Git으로 관리하는 코드를 인터넷에 저장·공유
```

내가 이해하기 쉬웠던 표현:

```text
Git
→ 로컬 세이브 시스템 💾

GitHub
→ 인터넷 저장소 ☁️
```

---

# 3. 기본 명령어

처음에는 우선 네 가지를 중심으로 이해했다.

```bash
git add
```

```text
"이 변경사항을 다음 저장에 포함할 거야."
```

```bash
git commit
```

```text
"현재 상태를 하나의 기록으로 저장."
```

```bash
git push
```

```text
"내 로컬 기록을 GitHub에 올려."
```

```bash
git pull
```

```text
"GitHub의 최신 내용을 내 컴퓨터로 가져와."
```

기본 흐름은:

```text
파일 수정
   ↓
git add
   ↓
git commit
   ↓
git push
```

---

# 4. commit 중 편집기 오류

이전에 `git commit`을 실행하면서:

```text
hint: Waiting for your editor to close the file...
error: cannot spawn code
```

같은 메시지를 본 적이 있었다.

처음에는 Git 자체가 고장 난 줄 알았다.

하지만 의미는:

> Git이 commit 메시지를 작성하기 위해  
> VS Code의 `code` 명령을 실행하려 했는데 찾지 못했다.

는 상황이었다.

즉 Git 전체가 망가진 것은 아니었다.

---

# 5. 저장소 폴더를 잘못 보고 있었다

작업 중 두 개의 저장소가 있었다.

```text
/c/code
├── git
└── gitproject
```

그런데 나는:

```text
/c/code/gitproject
```

에서 `git status`를 실행하고 있었다.

실제로 확인해야 했던 저장소는:

```text
/c/code/git
```

였다.

그래서:

```bash
cd ../git
```

로 이동했다.

---

# 💡 Git에서는 현재 위치가 중요하다

같은 명령어라도:

```text
어느 폴더에서 실행하느냐
```

에 따라 완전히 다른 저장소의 상태를 보게 된다.

이날 크게 배운 것:

> **Git 명령을 실행하기 전에 현재 폴더부터 확인하자.**

---

# 6. git status

저장소를 제대로 이동한 뒤:

```bash
git status
```

를 실행했다.

결과:

```text
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
```

처음에는 또 문제가 생긴 줄 알았다.

하지만 하나씩 보면:

```text
On branch main
→ 현재 main 브랜치에 있음
```

```text
up to date with 'origin/main'
→ 로컬 main과 GitHub의 main이 같은 상태
```

```text
nothing to commit
→ 새로 저장할 변경사항 없음
```

```text
working tree clean
→ 수정 후 아직 처리하지 않은 파일도 없음
```

즉 정상 상태였다.

---

# 7. MERGING이 사라졌다

이전에는 프롬프트에서:

```text
(main|MERGING)
```

처럼 merge 진행 상태가 있었고  
파일 충돌도 발생했던 기록이 있었다.

그런데 다시 확인했을 때는:

```text
(main)
```

으로 바뀌어 있었다.

그래서 merge가 실제로 어떻게 끝났는지 확인하기 위해:

```bash
git log --oneline --graph --decorate -5
```

를 실행했다.

---

# 8. Git log 읽기

결과:

```text
*   bbe6dc6 (HEAD -> main, origin/main) 로그인 기능 충돌 해결
|\
| * 539540c 네이버 로그인 가능 구현 완료
* | b6ae053 네이버 로그인 기능 구현 완료
|/
* e46997b 카카오톡 로그인 기능 구현 완료
* c581d34 실험적인 구글 로그인 기능의 테스트가 완료되어 원래의 프로그램에 반영하였습니다.
```

처음에는 `|`, `\`, `*`가 왜 저렇게 많은지 또 당황했다. 😂

하지만 이건 커밋들이 갈라졌다가 다시 합쳐진 흐름을 보여주는 그래프였다.

---

# 9. Merge Commit

가장 위의:

```text
bbe6dc6 로그인 기능 충돌 해결
```

은 두 작업 흐름을 다시 합친 **merge commit**이었다.

그래프의:

```text
|\
| *
* |
|/
```

모양이 두 갈래가 나뉘었다가 합쳐졌다는 것을 보여준다.

---

# 10. HEAD와 origin/main

로그에:

```text
(HEAD -> main, origin/main)
```

이라고 표시되어 있었다.

이를 나누면:

```text
HEAD -> main
→ 현재 내가 보고 있는 로컬 브랜치가 main

origin/main
→ GitHub 원격 저장소의 main
```

그리고 둘이 같은 커밋:

```text
bbe6dc6
```

을 가리키고 있었다.

즉:

```text
내 컴퓨터 main
        ↓
     bbe6dc6
        ↑
GitHub origin/main
```

로컬과 GitHub가 같은 상태였다.

---

# 11. commit 했는데 아무 일도 안 일어났다

다음 명령을 실행했다.

```bash
git commit -m "인스타그램 로그인 기능을 추가했습니다."
```

그런데:

```text
nothing to commit, working tree clean
```

이 계속 나왔다.

처음에는 commit 명령어가 안 먹는 줄 알았다.

하지만 의미는:

> **지난 commit 이후 실제 파일 변경사항이 하나도 없다.**

였다.

즉 commit 메시지만 새로 쓴다고  
새로운 commit이 생기는 것은 아니었다.

---

# 12. commit이 만들어지는 흐름

실제 변경이 있어야 한다.

```text
① 파일 수정
     ↓
② git add
     ↓
③ git commit
     ↓
④ git push
```

예를 들어 파일을 수정했다면:

```bash
git status
```

에서:

```text
modified: 파일이름
```

같은 변화가 보여야 한다.

---

# 13. 수정했다고 생각했는데 clean이라면?

내가 분명 무언가 수정했다고 생각했는데:

```text
working tree clean
```

이라고 나온다면,

먼저 현재 Git 저장소 안의 파일을 수정한 것이 맞는지 확인해야 한다.

확인에 사용할 수 있는 명령:

```bash
git status
```

그리고:

```bash
ls
```

Git 문제처럼 보여도 실제 원인은:

> **다른 폴더에서 작업하고 있었던 것**

일 수도 있었다.

---

# 14. Ctrl + C

터미널에:

```text
^C
```

가 표시되기도 했다.

이건:

```text
Ctrl + C
→ 현재 실행 중인 명령 중단
```

이라는 뜻이었다.

Git 저장소를 망가뜨린 것이 아니었다. 😮‍💨


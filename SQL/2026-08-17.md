## 📌 오늘의 기록

오늘의 주제:

> **SQL 문법보다 무서운 오타**

직접 작성한 Query와 답안을 비교하면서  
왜 내가 작성한 SQL만 오류가 나는지 확인했다.

결론은...

`.` 하나였다. 😂

그리고 잠시 후 `갤럭시`도 실종됐다.

---

# 1. INSERT 문에서 Error 1054

내가 직접 작성한 INSERT 문에서 오류가 발생했다.

문제 부분:

```sql
INSERT INTO customers
(name, email. password, address, join_date)
```

처음에는 SQL 문법이나 데이터 구조가 잘못된 줄 알았다.

하지만 자세히 보니:

```text
email. password
      ↑
      .
```

마침표가 들어가 있었다.

원래는:

```sql
INSERT INTO customers
(name, email, password, address, join_date)
```

처럼 쉼표를 사용해야 했다.

```text
email. password  ❌

email, password  ✅
```

---

# 🚨 Error Code: 1054

오류 메시지:

```text
Error Code: 1054.
Unknown column 'email.password' in 'field list'
```

MySQL은 내가 쓴:

```text
email.password
```

를 하나의 컬럼처럼 해석한 것이다.

그래서:

> **email.password라는 컬럼은 없는데요?**

라고 오류를 냈다.

---

# 2. 답안은 되는데 왜 내 것만 안 되지?

당시 문제의:

```text
1 ~ 4번 → 내가 직접 작성
6 ~ 9번 → 답안 복사
```

였다.

답안은 실행됐는데 내가 작성한 Query만 오류가 나서  
내용을 비교해봤고 결국 `.` / `,` 차이를 발견했다.

이 경험으로 오류가 발생했을 때  
정답과 내 코드를 **한 글자씩 비교하는 것도 중요하다**는 걸 배웠다.

---

# 3. OR로 여러 값 조회하기

작성한 Query:

```sql
SELECT *
FROM products
WHERE name = '갤럭시'
   OR name = '아이폰'
   OR name = '에어팟';
```

결과:

```text
갤럭시
아이폰
에어팟
```

세 상품이 정상적으로 조회됐다.

---

# 4. IN으로 바꿨더니 갤럭시가 사라졌다

같은 조건을 `IN`으로 작성했다.

```sql
SELECT *
FROM products
WHERE name IN ('갤력시', '아이폰', '에어팟');
```

그런데 결과에서 **갤럭시만 사라졌다.**

처음에는:

```text
"IN이 OR하고 다른 건가?"
```

라고 생각했다.

하지만 또 오타였다.

```text
갤럭시 ✅
갤력시 ❌
```

---

# 😂 갤럭시 실종 사건

```sql
WHERE name IN ('갤력시', '아이폰', '에어팟');
```

MySQL은 아주 정확하게:

```text
"갤력시라는 상품은 없는데요?"
```

라고 판단한 것이다.

그래서 실제 데이터인 `갤럭시`는 조회되지 않았다.

수정:

```sql
SELECT *
FROM products
WHERE name IN ('갤럭시', '아이폰', '에어팟');
```

---

# 5. OR와 IN

오늘 비교하면서 알게 된 것:

```sql
WHERE name = '갤럭시'
   OR name = '아이폰'
   OR name = '에어팟';
```

는 같은 컬럼에서 여러 값을 찾을 때:

```sql
WHERE name IN ('갤럭시', '아이폰', '에어팟');
```

처럼 더 짧게 표현할 수 있다.

```text
OR
→ 조건을 하나씩 반복

IN
→ 여러 후보를 한 번에 지정
```

# 🔍 오늘 생긴 디버깅 습관

Query 결과가 이상하면 어려운 문법부터 의심하지 말고  
먼저 아주 작은 부분을 확인하자.

```text
1. 쉼표 , 와 마침표 . 확인

2. 철자 확인

3. 따옴표 확인

4. 괄호 확인

5. 컬럼명 확인
```

오늘은 실제로:

```text
email. password
```

와

```text
갤력시
```

때문에 한참 헤맸다.

```text

→ 실제 저장된 값과 철자가 맞아야 함
```

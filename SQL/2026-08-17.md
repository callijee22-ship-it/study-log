# 🚨 Error 1054 — Unknown column

실습 문제를 직접 작성해서 실행했는데  
오류가 발생했다.

당시 화면에서 확인한 핵심 메시지:

```text
┌───────────────────────────────────────────────┐
│ Error Code: 1054                              │
│ Unknown column ...                            │
└───────────────────────────────────────────────┘
```

처음에는 SQL 문법이나 문제 풀이 방식이  
완전히 잘못된 줄 알았다.

그런데 원인을 확인해보니:

```text
.
```

작은 문자 하나가 잘못 들어가 있었다.

### 💡 여기서 배운 것

`Unknown column`이라는 메시지가 나오면  
무조건 어려운 문제라고 생각할 필요가 없다.

먼저:

```text
Column 이름
철자
. / ,
따옴표
```

같은 오타부터 확인한다.

### ⭐ 기억하기

```text
1054 Unknown column
→ Column 이름과 오타 확인
```

# 🔎 WHERE

특정 조건을 만족하는 데이터만 조회할 때  
`WHERE`를 사용한다.

예:

```sql
SELECT *
FROM products
WHERE name = '갤럭시';
```

의미:

```text
products Table에서

name이 '갤럭시'인 Row만

보여줘.
```

### ⭐ 기억하기

```text
WHERE = 조건
```

---

# 🔗 OR

여러 조건 중 하나라도 만족하는 데이터를 찾을 수 있다.

```sql
SELECT *
FROM products
WHERE name = '갤럭시'
   OR name = '아이폰'
   OR name = '에어팟';
```

결과:

```text
┌────────────┐
│ name       │
├────────────┤
│ 갤럭시     │
│ 아이폰     │
│ 에어팟     │
└────────────┘
```

### ⭐ 기억하기

```text
OR
= 여러 조건 중 하나라도 참
```

---

# 📋 IN

같은 Column에서 여러 값을 찾을 때  
`OR`를 계속 작성하지 않고 `IN`을 사용할 수 있다.

기존 방식:

```sql
SELECT *
FROM products
WHERE name = '갤럭시'
   OR name = '아이폰'
   OR name = '에어팟';
```

짧게 바꾸면:

```sql
SELECT *
FROM products
WHERE name IN ('갤럭시', '아이폰', '에어팟');
```

의미는 같다.

### 💡 내가 이해한 방식

```text
A이거나
B이거나
C이거나

       ↓

IN (A, B, C)
```

### ⭐ 기억하기

```text
WHERE Column IN (값1, 값2, 값3)
```

# 😭 IN을 썼더니 갤럭시가 사라졌다

먼저 `OR`로 조회했다.

```sql
SELECT *
FROM products
WHERE name = '갤럭시'
   OR name = '아이폰'
   OR name = '에어팟';
```

결과:

```text
┌────────────┐
│ 갤럭시     │
│ 아이폰     │
│ 에어팟     │
└────────────┘
```

정상적으로 세 개가 모두 나왔다.

이번에는 같은 의미로 `IN`을 사용했다.

```sql
SELECT *
FROM products
WHERE name IN ('갤력시', '아이폰', '에어팟');
```

그런데 결과:

```text
┌────────────┐
│ 아이폰     │
│ 에어팟     │
└────────────┘

??? 갤럭시 어디감 ???
```

처음에는:

```text
IN 사용법이 틀렸나?
```

라고 생각했다.

하지만 두 SQL을 다시 비교했다.

```text
OR에서 입력한 값

갤럭시
   ↑
   럭


IN에서 입력한 값

갤력시
   ↑
   력
```

원인은 문법이 아니라:

```text
갤럭시 ≠ 갤력시
```

단순 오타였다. 😂

---

# 🧠 SQL은 입력한 값을 정확하게 비교한다

사람 눈에는 비슷하게 보이지만  
SQL 입장에서는 완전히 다른 문자열이다.

```text
'갤럭시'

≠

'갤력시'
```

Database에 `갤력시`라는 상품이 없다면  
당연히 검색 결과에도 나오지 않는다.

### ⭐ 기억하기

```text
문법이 맞아도
검색값이 틀리면
원하는 결과는 나오지 않는다.
```

---

# 🤔 OR vs IN

처음에는 둘이 서로 다른 기능처럼 느껴졌다.

하지만 같은 Column에서 여러 값을 찾는 경우:

```sql
name = '갤럭시'
OR name = '아이폰'
OR name = '에어팟'
```

은:

```sql
name IN ('갤럭시', '아이폰', '에어팟')
```

처럼 간단하게 작성할 수 있다.

### 화면으로 보면

```text
OR 방식

name = A
   OR
name = B
   OR
name = C


       ↓ 같은 의미


IN 방식

name IN (A, B, C)
```

### ⭐ 기억하기

```text
같은 Column의 여러 값 조회
→ IN을 사용하면 간단함
```

# 💡 오늘 다시 이해한 내용

SQL의 실행 결과는 다음이 모두 정확해야 한다.

```text
SQL 문법

+

Column 이름

+

Database에 저장된 실제 값

+

내가 입력한 검색 값
```

즉 문법만 맞다고 끝이 아니다.

예를 들어:

```sql
WHERE name IN ('갤력시', '아이폰', '에어팟');
```

는 SQL 문법 자체는 정상이다.

하지만 `갤력시`라는 값이 Database에 없다면  
그 Row는 조회되지 않는다.

---

# 🧪 오늘의 디버깅 흐름

오늘 실제로 한 과정:

```text
쿼리 실행
   ↓
결과가 이상함
   ↓
"IN이 잘못된 건가?"
   ↓
OR Query와 비교
   ↓
한 글자 차이 발견
   ↓
갤력시 → 갤럭시
   ↓
다시 실행
   ↓
정상 결과 ✅
```

이 과정을 직접 해보면서  
SQL을 공부할 때도 **비교하면서 오류를 찾는 것**이 중요하다는 걸 배웠다.

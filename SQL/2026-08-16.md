# 1. SQL에서 "초기화"는 하나가 아니었다

처음에는 그냥 모든 것을 초기화하는 명령이 하나 있을 거라고 생각했다.

하지만 실제로는 무엇을 초기화하고 싶은지에 따라 달랐다.

```text
① 데이터만 삭제
   → 테이블 구조 유지

② 테이블 삭제
   → 테이블 구조까지 제거

③ Database / Schema 삭제
   → 내부 테이블과 데이터까지 전부 제거
```

즉,

> **"초기화"라고 하기 전에 무엇을 지우려는지 먼저 구분해야 한다.**

---

# 2. Error Code: 3734

테이블을 다시 만드는 과정에서 다음 오류가 발생했다.

```text
Error Code: 3734

Failed to add the foreign key constraint.

Missing column 'customer_id'
for constraint 'fk_orders_customers'
in the referenced table 'customers'
```

처음 보면 굉장히 무서운 문장이었다. 😂

사람말로 바꾸면:

> `orders`에서 `customers.customer_id`를 참조하려는데  
> 실제 customers 테이블에 customer_id가 없습니다.

---

# 🔗 Foreign Key 다시 이해하기

구조는 이런 느낌이었다.

```text
orders.customer_id
        │
        ▼
customers.customer_id
```

외래키는

> **다른 테이블의 실제 존재하는 컬럼을 가리키는 연결**

이다.

따라서:

```sql
REFERENCES customers(customer_id)
```

라고 작성했다면  
실제 `customers` 테이블에도 `customer_id`라는 컬럼이 있어야 한다.

---

# 3. 그런데 내가 적은 CREATE TABLE에는 customer_id가 있었다

작성한 SQL에는 분명히:

```sql
CREATE TABLE customers (
    customer_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);
```

가 있었다.

그리고 `orders`도:

```sql
CREATE TABLE orders (
    order_id INT AUTO_INCREMENT PRIMARY KEY,
    customer_id INT NOT NULL,
    order_date DATETIME DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT fk_orders_customers
        FOREIGN KEY (customer_id)
        REFERENCES customers(customer_id)
);
```

처럼 작성했다.

SQL만 보면 연결이 맞아 보였다.

---

# 4. 기존 테이블이 남아 있을 수 있다

원인은 이전에 생성했던 `customers` 테이블이  
DB 안에 그대로 남아 있었을 가능성이었다.

내가 새로 작성한 SQL은:

```text
customers
├── customer_id
└── name
```

을 기대하고 있지만,

실제 DB에는 과거에 만들었던 다른 구조의 `customers`가 남아 있다면:

```text
customers
├── id
└── name
```

처럼 되어 있을 수도 있다.

그러면:

```sql
REFERENCES customers(customer_id)
```

에서 오류가 발생한다.

---

# 5. DROP TABLE로 다시 만들기

실습용 데이터라 기존 데이터를 지워도 괜찮은 상황에서는  
테이블을 삭제하고 다시 생성할 수 있었다.

```sql
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS customers;
```

여기서 **순서가 중요했다.**

```text
orders
   │
   └────→ customers
```

`orders`가 `customers`를 참조하고 있기 때문에  
자식 테이블인 `orders`부터 먼저 삭제하는 것이 안전했다.

```text
자식 삭제
   ↓
부모 삭제
```

# 6. Error Code: 1046

테이블을 다시 만들려고 했더니 이번에는:

```text
Error Code: 1046.
No database selected
```

오류가 발생했다.

뜻:

> **현재 사용할 Database가 선택되어 있지 않습니다.**

MySQL 입장에서는:

```text
"customers 테이블을 만들라는 건 알겠는데
어느 DB에 만들라는 거야?"
```

라는 상태였다.

---

# 7. Database 선택하기

방법은 두 가지가 있었다.

### Workbench에서 선택

왼쪽 `SCHEMAS` 목록에서 사용할 Database를  
더블클릭한다.

선택되면 기본 DB가 된다.

### SQL로 선택

```sql
USE 데이터베이스명;
```

예를 들어:

```sql
USE my_shop;
```

처럼 사용할 수 있다.

그 뒤:

```sql
CREATE TABLE ...
```

을 실행하면 선택한 DB 안에 테이블이 만들어진다.

---

# 🧠 오늘 이해한 것

```text
DROP TABLE
→ 테이블 자체 삭제

DROP DATABASE
→ Database 자체 삭제

Foreign Key
→ 부모 테이블의 실제 컬럼을 참조

Error 3734
→ Foreign Key가 참조하는 컬럼을 찾지 못함

Error 1046
→ 사용할 Database를 선택하지 않음

USE database_name;
→ 사용할 Database 지정
```

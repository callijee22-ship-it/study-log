# 🚨 첫 번째 오류 — Database를 선택하지 않음

처음 `sample` 테이블을 조회하려고 했다.

```sql
SELECT * FROM sample;
```

당시 화면:

```text
┌──────────────────────────────────────────────────────────┐
│ Action Output                                            │
├──────────────────────────────────────────────────────────┤
│ Error Code: 1046. No database selected                  │
│                                                          │
│ Select the default DB to be used by double-clicking     │
│ its name in the SCHEMAS list in the sidebar.            │
└──────────────────────────────────────────────────────────┘
```

처음에는 SQL 문장이 틀린 줄 알았다.

하지만 실제 의미는:

```text
"어느 Database에서
 sample 테이블을 찾아야 하는지 모르겠어요."
```

였다.

### 해결 방법

MySQL Workbench 왼쪽 `SCHEMAS`에서  
사용할 Database를 더블클릭한다.

```text
SCHEMAS

▼ my_shop   ← 사용할 DB 선택
  ├─ Tables
  ├─ Views
  └─ ...
```

SQL로 직접 선택할 수도 있다.

```sql
USE 데이터베이스명;
```

### ⭐ 기억하기

```text
Error 1046
= Database가 선택되지 않음
```

# 🔍 첫 SELECT 성공

Database를 선택한 뒤 다시 실행했다.

```sql
SELECT * FROM sample;
```

이번에는 정상적으로 결과가 나왔다. ✅

SQL을 하나씩 나눠서 이해했다.

```text
SELECT = 보여줘

* = 모든 컬럼

FROM = 어디에서?

sample = sample 테이블
```

그래서 전체 의미는:

```text
sample 테이블에서
모든 컬럼을 보여줘.
```

```sql

```

의미:


# 🏗️ 테이블 만들기

고객, 상품, 주문을 관리하기 위한 테이블을 만들기 시작했다.

```text
customers = 고객

products = 상품

orders = 주문
```

이 과정에서 Primary Key와 Foreign Key도 처음 접했다.

---

# 🆔 ID 컬럼에서 첫 실수

상품 번호를 다음처럼 만들었다.

```sql
product_id INT NOT NULL
```

그런데 외래키를 작성하면서:

```text
product_id
```

와

```text
products_id
```

를 섞어서 사용했다.

SQL에서는 둘이 완전히 다른 이름이다.

```text
product_id  ✅

products_id ❌
```

테이블 이름이 `products`라고 해서  
컬럼 이름도 자동으로 `products_id`가 되는 것은 아니다.

---

# 🔗 Foreign Key

주문 테이블은 고객과 상품을 연결한다.

```text
customers
     ↑
     │ customer_id
     │
   orders
     │
     │ product_id
     ↓
products
```

즉 주문은:

```text
누가
+
어떤 상품을
+
몇 개 샀는지
```

기록하는 테이블이라고 이해했다.

---

# 🧠 Foreign Key를 내 방식대로 이해하기

Foreign Key는

> 다른 테이블의 데이터를 가리키는 손가락

이라고 이해했다.

```text
orders.customer_id
        │
        ↓
customers.customer_id
```

그리고 아주 중요한 점:

```text
Foreign Key가 가리키는 컬럼은
부모 테이블에 실제로 존재해야 한다.
```

---

# 🚨 Missing column 오류

Foreign Key를 연결하다가 이런 오류를 만났다.

```text
┌──────────────────────────────────────────────────────────┐
│ Missing column 'customer_id'                            │
│ for constraint 'fk_orders_customers'                    │
│ in the referenced table 'customers'                     │
└──────────────────────────────────────────────────────────┘
```

사람말로 바꾸면:

```text
orders에서 customers.customer_id를
가리키라고 했는데

현재 customers 테이블에
customer_id라는 컬럼이 없습니다.
```

였다.

---

# 🤔 그런데 SQL에는 customer_id가 있는데?

작성한 SQL에는 분명히 있었다.

```sql
CREATE TABLE customers (
    customer_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);
```

그래서 알게 된 것:

> 지금 화면에 작성한 SQL과  
> 실제 Database 안에 이미 존재하는 테이블 구조는 다를 수 있다.

예전에 만든 `customers` 테이블이 남아 있다면  
새 `CREATE TABLE` 코드를 적는 것만으로 기존 테이블이 바뀌지는 않는다.

---

# 🧹 기존 테이블 삭제 후 재생성

실습 데이터가 중요하지 않을 경우  
기존 테이블을 삭제한 뒤 다시 만들 수 있다.

하지만 삭제 순서가 중요했다.

```text
orders
   ↓
customers
```

`orders`가 `customers`를 참조하고 있기 때문에  
자식 테이블인 `orders`를 먼저 삭제한다.

```sql
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS customers;
```

### ⭐ 기억하기

```text
Foreign Key 관계가 있다면

자식 Table 먼저 삭제
→ 부모 Table 삭제
```

# ✅ orders 테이블 생성 성공

문법과 컬럼 이름을 수정하고 다시 실행했다.

그러자:

```text
┌─────────────────────────────┐
│ ✔ 0 row(s) affected         │
└─────────────────────────────┘
```

가 나타났다.

이건 실패가 아니라  
**테이블 생성이 정상적으로 완료되었다는 뜻**이었다.

---

# 🚨 Error 1050 — Table already exists

성공한 뒤 같은 `CREATE TABLE orders`를 다시 실행했다.

결과:

```text
┌──────────────────────────────────────────┐
│ Error Code: 1050                         │
│ Table 'orders' already exists            │
└──────────────────────────────────────────┘
```

뜻은:

```text
"orders 테이블 이미 있는데요?"
```

였다.

즉 이 오류는 오히려  
**앞에서 테이블 생성에 성공했다는 증거**이기도 했다.

### ⭐ 기억하기

```text
1050
= 같은 이름의 Table이 이미 존재
```

---

# 🧾 DESCRIBE로 테이블 구조 확인

주문 데이터를 넣으려고 했는데  
고객정보를 어떻게 입력해야 할지 몰랐다.

그래서:

```sql
DESCRIBE customers;
```

를 실행했다.

당시 확인한 구조:

```text
┌─────────────┬──────────────┬───────────────┐
│ Column      │ 역할         │ 직접 입력?    │
├─────────────┼──────────────┼───────────────┤
│ customer_id │ 고객 번호    │ 자동 생성     │
│ name        │ 이름         │ 직접 입력     │
│ email       │ 이메일       │ 직접 입력     │
│ password    │ 비밀번호     │ 직접 입력     │
│ address     │ 주소         │ 직접 입력     │
│ join_date   │ 가입 시간    │ 기본값 사용   │
└─────────────┴──────────────┴───────────────┘
```

실제 테이블 생성 SQL:

```sql
CREATE TABLE customers (
    customer_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    address VARCHAR(255) NOT NULL,
    join_date DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### ⭐ 기억하기

```text
DESCRIBE
= Table의 구조 확인
```

# ➕ 첫 고객 데이터 INSERT

테이블 구조를 확인한 뒤  
테스트 고객을 추가했다.

```sql
INSERT INTO customers (name, email, password, address)
VALUES ('홍길동', 'hong@example.com', '1234', '서울시 강남구');
```

확인:

```sql
SELECT * FROM customers;
```

`customer_id`는 AUTO_INCREMENT이므로 자동으로 생성된다.

`join_date`도 기본값이 있기 때문에 자동으로 현재 시간이 들어간다.

# 🚨 Error 1452 — 주문을 넣을 수 없음

처음에는 고객 데이터가 없는 상태에서 주문을 넣으려고 했다.

```sql
INSERT INTO orders (customer_id, product_id, quantity)
VALUES (1, 1, 1);
```

당시 오류:

```text
┌──────────────────────────────────────────────────────────┐
│ Error Code: 1452                                        │
│                                                          │
│ Cannot add or update a child row:                       │
│ a foreign key constraint fails                          │
└──────────────────────────────────────────────────────────┘
```

처음에는 주문 SQL이 잘못된 줄 알았다.

하지만 실제 상황은:

```text
orders.customer_id = 1
          │
          ↓
customers.customer_id = 1

❌ 1번 고객이 아직 존재하지 않음
```

이었다.

---

# 🔗 부모 데이터가 먼저 필요하다

Foreign Key로 연결되어 있기 때문에  
주문을 만들기 전에 고객과 상품이 실제로 존재해야 한다.

순서:

```text
① customers에 고객 추가

        ↓

② products에 상품 존재 확인

        ↓

③ orders에 주문 추가
```

상품도 확인한다.

```sql
SELECT * FROM products;
```

`product_id = 1`인 상품이 존재한다면:

```sql
INSERT INTO orders (customer_id, product_id, quantity)
VALUES (1, 1, 1);
```

을 실행할 수 있다.

### ⭐ 기억하기

```text
부모 데이터 먼저
자식 데이터 나중
```

---

# 🛒 고객 → 상품 → 주문

오늘 가장 중요하게 이해한 구조이다.

```text
customers
     │
     │
     └──────┐
            ↓
          orders
            ↑
     ┌──────┘
     │
products
```

주문은 독립적으로 생기는 것이 아니라

```text
존재하는 고객
+
존재하는 상품
```

을 연결한다.

Foreign Key 관련 실습 중

이때 배운 것:

```text

```

그리고 SQL에서도 작은 철자 하나가 중요하다.

# 🤔 오늘 헷갈렸던 것

### Database 선택 문제 vs SQL 문법 문제

```text
1046
= SQL 문장이 틀린 것이 아님
= 사용할 DB가 선택되지 않음
```

### 테이블 이름 vs 컬럼 이름

```text
products라는 Table
≠
products_id라는 Column
```

실제 정의한 컬럼 이름을 사용해야 한다.

### Foreign Key

단순히 이름만 연결하는 것이 아니라:

```text
참조 대상 Column이 실제로 존재해야 하고

참조할 부모 Row도 실제로 존재해야 한다.
```

### 오류가 떴다고 항상 실패한 것은 아님

```text
CREATE TABLE 성공
        ↓
같은 코드 다시 실행
        ↓
1050 Already exists
```

이 경우 앞 실행은 성공한 것이다.

# 💡 오늘 다시 이해한 전체 흐름

오늘 하루에 배운 내용을 연결하면:

```text
Database 선택
      ↓
Table 생성
      ↓
Column 정의
      ↓
Primary Key 설정
      ↓
Foreign Key로 Table 연결
      ↓
부모 Data 입력
      ↓
자식 Data 입력
      ↓
SELECT로 조회
```

SQL은 문장 하나만 작성하는 것이 아니라  
Database와 Table의 구조를 이해하는 것이 중요했다.

그리고 가장 중요한 습관:

> 오류가 발생하면 코드 전체를 갈아엎기 전에  
> 오류 메시지가 뭐라고 말하는지 먼저 읽어보기.

---

# ⭐ 오늘의 한 줄 암기

```text
SELECT = 조회
* = 모든 Column
FROM = 어느 Table에서

INSERT INTO = Data 추가
DESCRIBE = Table 구조 확인

PRIMARY KEY = 각 Row를 구분
FOREIGN KEY = 다른 Table과 연결

1046 = Database 선택 안 됨
1064 = SQL 문법 오류
1050 = Table 이미 존재
1452 = 참조할 부모 Data 없음

Foreign Key:
부모 Data 먼저
→ 자식 Data 나중

DROP:
자식 Table 먼저
→ 부모 Table 나중
```

## 🌱 오늘의 기록

SQL 첫날.

처음 `SELECT`부터 오류가 났고  
테이블을 만들다가 또 오류가 났고  
Foreign Key에서도 오류가 났고  
데이터를 넣다가 또 오류가 났다.

하지만 하나씩 오류를 확인하면서

```text
Database
Table
Column
Primary Key
Foreign Key
INSERT
SELECT
```

가 어떻게 연결되는지 조금씩 이해하기 시작했다.

결국 오늘 가장 크게 배운 것은:

> **오류가 떴다고 망한 게 아니다.  
> 메시지를 읽으면 이유가 적혀 있다.**
